# VWARD: правила проекта

## Название веб-интерфейса

Веб-интерфейс VWARD называется только **«Панель VWARD»** (решение владельца 2026-09-27,
окончательное). В английских текстах и комментариях - «VWARD Panel» / «the Panel».

Не использовать: «Console», «Консоль», «консоль управления», «центр управления»,
«веб-интерфейс VWARD». Если владелец в разговоре называет её консолью - поправить:
«это Панель VWARD».

Внутренние имена файлов и параметров остаются прежними, их не видит пользователь, а
переименование сломало бы обновление установленных роутеров: `web/assets/vward-console.*`,
`S93vward-console`, компонент `console`, `VWARD_CONSOLE_PORT`, `vward-console-config.sh`,
тесты `check-console-*`.

## Claude Code и Codex: правила совместной разработки

- Claude Code и Codex — поочерёдные исполнители; GitHub/PR/точный HEAD — единственный способ передачи состояния. Не повторяй сделанную работу и не изменяй одновременно ветку другого агента.
- Применяй общие правила `AGENTS.md` и обязательные требования `docs/AGENT.md` / `docs/ROADMAP.md`. Перед изменениями читай только релевантный код и нужные разделы дополнительных документов, не копируй в контекст весь журнал повторно без причины.
- Для текущего направления учитывай `docs/ROUTING_B_IMPLEMENTATION.md`, `docs/ROUTING_AUDIT_CONTRACT.md`, `docs/RS6_READ_ADAPTERS.md` и интеграционный отчёт `docs/P7_B_INTEGRATION_2026-10-31.md`.
- В архитектуре B защищай чужие/unknown группы, права управления, DNS/AGH, сохранённое состояние и recovery. До отдельного разрешения RS-6 остаётся только read-only/audit: **без применения маршрутов, DNS и подключения writer**.
- Работу пакета выполняет один доступный агент, второй её не дублирует. Независимый аудит — адресный: только для рискованных изменений (запись в маршрутизацию, переключение DNS, восстановление после сбоев), не обязательный шаг перед каждым этапом.
- Минимальный доказанный фикс, регрессия RED→GREEN, целевые тесты и один необходимый полный CI на конечном HEAD. Не ослабляй production admission, тесты или ресурсные бюджеты.
- **До «Выпускаем»** не сливай в `dev`/`main`, не меняй публикационную версию/feed, не запускай подпись/релиз, не устанавливай обновление. Для любых действий на Keenetic/VPN/AGH нужно отдельное явное разрешение.
- Экономь лимиты: предлагай подходящую доступную модель и усилие до большого пакета; при переключении на новый пакет или другого агента закрепляй HEAD, результаты тестов и открытые вопросы, затем начинай новую сессию. Новая сессия не сбрасывает лимиты.
