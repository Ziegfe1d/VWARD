# План VWARD

Единственный план VWARD: что дальше и в каком порядке. Как вести:

- **Сделанное** записывается в [`CHANGELOG.md`](../CHANGELOG.md), по выпускам. Пункт, который вошёл в
  выпуск, отсюда удаляется.
- **Решения владельца** собраны в разделе 6. Новое решение - сразу туда, с датой.
- **Справка, а не план:** [`ARCHITECTURE.md`](ARCHITECTURE.md) (устройство, агенты, движки туннелей),
  [`STABILITY.md`](STABILITY.md) (индекс устойчивости, реальные сбои, технологические карты),
  [`RELEASE_0.2.0.md`](RELEASE_0.2.0.md) (как публикуется выпуск), [`INSTALL.md`](INSTALL.md),
  [`PANEL.md`](PANEL.md), [`UI_MENU_SPEC.md`](UI_MENU_SPEC.md), документы рекламы и обновлений.
- 2026-10-11 сюда сведены и удалены прежние планы: `MASTER_PLAN_0.2_TO_FINAL.md`, `DEV_0.2_PLAN.md`,
  `RC2_PLAN.md`, `FIX_PLAN_RC2_FIX1.md`, `PLAN_NEXT_RELEASE.md`, `FUTURE_BACKLOG.md`,
  `AGENTS_PLAN.md`, `PANEL_REWORK.md`, `DEV8_FINALIZATION_REPORT.md`, этапы из
  `STABILITY_ROADMAP.md`. Их текст - в истории git.

## 1. Где мы сейчас

- Ветка `dev`: **0.2.0-rc.2.fix.22**, этап RC2. Роутер владельца (Viva KN-1913, KeeneticOS 5.1)
  на `0.2.0-rc.2.fix.20`.
- Роутер владельца не скачивает по HTTPS: OpenSSL 3.5.5 из Entware падает на этом процессоре
  («Illegal instruction»), файлы не повреждены. fix.21 перевёл проверки связи на HTTP, fix.22
  скачивает через TLS Xray модуля VLESS. На роутер fix.22 ставится один раз командой вручную.
- Ветка `beta` (`0.1.9-beta`) - прежняя линия, новых выпусков нет.

## 2. Порядок работы

1. Сначала исправления ошибок, потом функции и оформление (владелец, 2026-10-11).
2. Сначала доказательство (код, тест, журнал, самотест роутера), потом вывод. Исправление - с
   тестом, который воспроизводит ошибку.
3. Не отключать Ed25519, SHA-256, проверку владельца файлов, защиту от понижения версии, копии,
   откат и барьер обновления.
4. Выпуск - когда CI зелёный; срочные и обычные исправления выпускаются без отдельного слова
   владельца (2026-10-10). Подпись - workflow `build-dev-release.yml`.
5. Команды для роутера - по стандарту Termius (`docs/STABILITY.md`, ТК-3); ключи, токены и адрес
   подписки не выводятся.

## 3. Этапы выпуска 0.2

`RC1 → RC2 → RP1 → RP2 → RETAIL`, версии `0.2.0-rc.1`, `0.2.0-rc.2`, `0.2.0-rp.1`, `0.2.0-rp.2`,
`0.2.0`; каждый этап - новый подписанный manifest с большим `sequence`. RC1 закрыт на
`0.2.0-rc.1.fix.19`.

- **RC2 (сейчас).** Исправления с тестами, стабильность и ресурсы; по решению владельца входят и
  функции. Обязательно: переход RC1→RC2, откат, прерванное обновление, восстановление WAN/DNS/
  GitHub, контроль флешки/процессора/памяти, 3-7 суток наблюдения.
- **RP1.** Заморозка кода. Воспроизводимая сборка с чистого клона, независимая проверка подписи,
  чистая установка, цепочка обновлений и откатов, выключение питания во время обновления, Панель
  на 320/390/1366 px, 7 суток без вмешательства. Critical/High: 0.
- **RP2.** Только исправления RP1 и документация; повтор выключения питания и отката;
  [`PUBLISHING_CHECKLIST.md`](PUBLISHING_CHECKLIST.md) без открытых пунктов.
- **RETAIL 0.2.0.** Только по слову владельца: код RP2, кроме версии; подписанный пакет,
  release notes, установка на роутер и проверка DNS, WAN, VPN, маршрутов, Панели, cron, журналов.

Доказательства каждого этапа: SHA коммита и ссылки CI, версия, суммы пакета и manifest, sequence,
проверка подписи, журналы установки/обновления/отката/перезагрузки, проверки DNS/WAN/VPN/маршрутов,
замеры процессора/памяти/флешки, известные риски.

## 5. Функции и оформление (после исправлений)

      переключатель «автоматически / вручную», как у VWARD.
- [ ] Проверка новых версий Xray и `vward-awg` без выпуска VWARD. Встроенное в прошивку -

## 6. Решения владельца (действуют)

- 2026-09-27 Туннель на любом Keenetic: VWARD сам решает, кто держит туннель - прошивка (умеет

  своей прошивки и своих модулей ядра не делаем. Новая прошивка 5.2: со стабильного канала -
  «Обновите прошивку Keenetic», только с тестового - с предупреждением; ставит владелец.
- 2026-09-28 VLESS через Xray, выключен по умолчанию.
- 2026-10-03 Ключ Amnezia Premium (`vpn://` с `api_key`): Панель только объясняет, что нужен файл
