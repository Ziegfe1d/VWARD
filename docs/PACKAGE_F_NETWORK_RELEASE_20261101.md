## 2. P0 — ожидающее обновление привязано к каналу

- `pending.state` хранит `feed=` — `manifest_url` и `manifest_v2_url`, с которых обновление найдено.
- `--apply-pending` (расписание, «Установить», «Повторить», после перезагрузки) отказывает, если `update.conf`
  **сейчас** (чтение файла, не памяти процесса) называет другой feed; каждое применение проверяет это ещё раз
  **внутри барьера обновления**, где Панель уже не может сменить канал — смена во время загрузки тоже ловится.
- Отказ: ничего не пишется, ожидающее обновление, канал и настройки остаются, фаза `IDLE`, строка в журнале и
  заметка в Панели. Возврат `dev → main → dev` — то же обновление применяется как обычно; подпись Ed25519,
  `sequence`, антиоткат не менялись. Ожидающее без привязки (старый движок) не применяется до следующей проверки.
  Свой feed и унаследованная `beta` привязываются так же.
- API: `pending.feed = current|other|unbound`; для «other» кнопки «Установить»/«Повторить» не предлагаются, Панель
  пишет «Найдено на другом канале», колокол и «Обзор» не объявляют его новым обновлением.
- Тест: `tests/updater/run-simulations.sh` (+19 случаев); на старом движке обновление `dev` ставилось на `main`.

## 3. r-lists — «Доменные списки»

- Управляемые списки: «Авто / Через VPN / Напрямую» — общий переключатель и у каждого списка. «Авто» включает
  слежение route engine и не меняет маршрут и домены; VPN/Напрямую — существующий writer `domain-list`
  (журнал, проверка, откат), затем слежение выключается; отказ маршрута не меняет ни список, ни слежение.
- Управление доказывается, а не угадывается: список принят владельцем (`list-adopt`, явное подтверждение
  `LIST_ADOPT`, пишется только `lists.conf` VWARD) или уже переключался владельцем через VWARD. Сервисные, AdaptiveAuto,
  «Мои домены», списки Keenetic и неизвестные — только показ.
- «Удалить выбранные»: точный предпросмотр (имена, число доменов, сколько идут через VPN), подтверждение, списки по
  одному через существующий `list delete` (копия настроек перед каждым), итог «готово N из M, не выполнено: …».
  «Отменить» удаление **не обещано**: доказанного поштучного восстановления нет.
- 0 списков — нормальное состояние: пояснение и переходы в «Сервисы» и «Мои домены»; ничего не создаётся и не
  копируется с чужого роутера.
- Остаток (блокер следующего пакета): создание/импорт списка из файла — нового способа записи в Keenetic не
  добавляли; массовые операции — последовательность отдельных транзакций, общей транзакции нет.

## 4. ads-ui, журналы, подсказки

- «Реклама и трекеры»: «Проверка VWARD» → «Списки и правила» → «Проверка блокировки» → «AdGuard Home» последним.
  Статусы: «Нет данных» (нет ответа/копия браузера), «Компонент выключен», «На паузе», «Нет подключения к AdGuard Home»,
  «выполняется», «последняя проверка с ошибкой», «N в очереди»; **зелёный только если проверка завершилась за
  последние 26 часов**, ожидание — серое. Доля блокировок: `191 / 38 232` → «≈ 0,5 %», ненулевая меньше 0,1 % →
  «< 0,1 %», без запросов — без доли.
- Журналы «Все»: по умолчанию **сначала новые**, выбор порядка хранится в браузере; продолжения записи остаются под
  её временем; по каждому источнику — время последнего события или «записей нет» / «ещё не создан» / «не читается»,
  отдельно от «Обновлено в …». API различает пустой, несозданный и нечитаемый журнал.
  **Причина «последние события 18.10» не доказана**: вероятный вклад — прежний порядок «старые сверху» при 200 строках
  от каждого источника (тихий источник уходит на недели назад); проверка — шаг 3 протокола ниже.
- «?»: у блока — сразу после заголовка; у главного блока страницы — в заголовке страницы сверху, а не отдельно;
  открывается нажатием и клавиатурой, фокус сохраняется.

## 5. Ворота для DNS/VPN/маршрутов (без изменений)

Двухэтапный барьер: тестируемый план без применения → адресный независимый аудит writer → только после явного
согласования владельца — включение и аппаратная проверка. В этом пакете ни один writer не подключался; r-lists
использует только существующие санкционированные операции Панели.

## 6. Протокол аппаратной приёмки (НЕ выполнялся; каждый шаг — по отдельному разрешению)

Шаг 1–3 — только чтение. Команды оформляются по `docs/termius-standard.md` (clear, подоболочка, ASCII, ≤60 символов,
OUT-файл, ротация) отдельным пакетом после согласования.

1. Entware: `opkg print-architecture`; `opkg info dnsmasq-full sing-box-go` (если индекс доступен); `uname -m`;
   свободное место `/opt`; без `opkg update/upgrade/install`.
2. Текущая сеть: `ndmc -c "show running-config"` (только `dns-proxy`, `object-group fqdn` — без URL/токенов),
   `ip rule`, `ip route show table all | head`, состояние AGH (GET), `free`, `top -b -n1 | head`.
3. Журналы «18.10»: для каждого файла из `api.cgi?action=log` — `ls -l`, `tail -n 1`, `date`; сравнить с тем, что
   показывает Панель (с новым порядком), отдельно свежие и архивные; часовой пояс роутера.
4. (Отдельное разрешение) загрузка `.ipk` в кэш без установки, сверка SHA256 с индексом, разбор `postinst`.
5. (Отдельное разрешение) установка «выключенным»; замер памяти/CPU; перезагрузка — остаётся выключенным.
6. (После адресного аудита writer и отдельного разрешения) переключение DNS-режима / движка туннеля.

## 7. Что требует независимого аудита

Перед любым включением writer: `vward_dns_mode_plan` → DNS-writer, `vward_vpn_engine_plan` → смена движка,
RS-7 writer маршрутов; изменения updater этого пакета (`vu_feed_bound`, проверка внутри барьера) — адресно,
как изменение пути применения обновлений.
