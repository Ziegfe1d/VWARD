## 2. Сделано в dev после выпуска rc.2 (на роутере не проверено)

- Захват DNS на LAN-интерфейсе вместо `any`, пауза при быстрых падениях (4, 8 … 60 с), `any` - вторым
  вариантом после трёх падений (`974d14c`, тест `check-route-engine-capture.py`).
- Нижняя панель не прыгает на телефоне: высота страницы по `dvh`, панель в своём слое, страница
  сохраняет высоту при обновлении данных (`c78c18d`).
- Страница «Реклама»: запросы параллельно (было 11,4 с, ожидается 1,5-2,5 с); очередь заданий
  рекламы запускается.
- Туннели (проверка добавления, переключателя и выключения):
  - адрес в туннеле, уже занятый другим туннелем, отклоняется до записи в роутер (создание и замена,
    в том числе контур AmneziaWG); два уже существующих туннеля с одним адресом - уведомление в Панели;
  - выключенный туннель нельзя назначить туннелем по умолчанию; если Keenetic не выключил туннель,
    программа контура включается обратно;
  - туннель по умолчанию, выключенный в настройках Keenetic: карточка VPN больше не пишет «трафик идёт
    через VPN», есть уведомление и пояснение на странице туннеля; сторож его не трогает;
  - импорт: если такая конфигурация или адрес уже есть - вопрос «Заменить / Добавить как новый /
    Отмена»; если сервер не ответил на рукопожатие - «Добавить всё равно?»; сообщения остаются в
    форме; ключ Amnezia Premium объясняется и не импортируется.

## 3. AdGuard Home при загрузке (главный пункт)

Без AdGuard Home у роутера нет DNS (его адрес - единственный name-server Keenetic).

**Сделано в dev (`check-agh-start-gate.py`, `check-boot-watch.py`):** все запуски VWARD (сторож
Панели `vward-cron-supervisor`, действие `dns-fail` сторожа `vward-sentinel`) идут через один шлюз
`vward_agh_ensure` в `vward-runtime-admission.sh`:
- запущен - ничего не делать;
- не запускать повторно, пока с прошлого запуска не прошло 120 с (AdGuard Home грузит списки
  минуту и больше, а запуск поверх запуска только перезапускает его);
- пауза после неудачного запуска растёт (120, 240, 480, 600 с), число попыток не ограничено,
  успешная работа в течение 120 с обнуляет счёт;
- устаревший PID-файл (нет процесса с этим номером или это другая программа) удаляется до запуска;
- два запускающих одновременно запускают один раз (блокировка);
- сторож Панели следит за AdGuard Home первые полчаса после загрузки (было 10 минут).

**Осталось (нужны данные с роутера):** установить причину. Команда `agh-boot-diag.sh` (только чтение)
даёт журнал AdGuard Home, проверку конфигурации `--check-config`, PID-файл, текст `S99adguardhome`
и список тех, кто его запускает. Гипотезы: запуски наступают друг на друга (закрыто шлюзом, кроме
ручного сторожа вне VWARD); устаревший PID-файл на флешке (закрыто); привязка к `192.168.1.1:65053`
до готовности сети; убийство процесса при нехватке памяти. Ручной сторож `S99zadguardhome-boot`
не из VWARD: после диагностики его нужно убрать на роутере, иначе он продолжает запускать AdGuard
Home мимо шлюза.

## 4. Туннели с одним адресом

Keenetic не принимает два туннеля с одним адресом (находка 5). Сделано в dev: отказ до записи в роутер
и уведомление «У двух туннелей один адрес» (`tunDupAddresses`, тест `check-console-tunnel-import.py`).

## 5. «argument parse error» (01:47)

Статический разбор всех команд `ndmc -c` в VWARD: имена доменов проверяются до отправки
(`valid_fqdn` в движке маршрутов, `valid_domain` в Панели), имена интерфейсов - `vward_valid_ndm_name`,
пути обнаружения доменов по умолчанию ничего не добавляют (`AUTO_ADD=0`). Источник не найден.
Нужна диагностика роутера: журнал действий Панели (`console-audit.log`) и журналы сторожей около 01:47.

## 6. Проверка и выпуск

1. Все наборы тестов (`run-all`), эмуляторы роутера, CI на dev.
2. На роутере, после установки: перезагрузка; через 3 минуты - AdGuard Home работает, `tcpdump`
   один, движок маршрутов работает, нет `SIGSEGV` в журнале; Панель открывается; нижняя панель стоит;
   страница «Реклама» открывается быстро (`ads-page-check.sh`).
3. Токен Aeternia попадает в самотесты Keenetic через аргументы процесса (`https-dns-proxy`):
   владельцу предложено сменить токен и не отправлять самотесты наружу.
4. Только после этого - «выкатывай», подпись и публикация `0.2.0-rc.2.fix.1`.

Порядок работ: диагностика роутера (п. 3, 5) → проверка в dev на роутере → выпуск.
