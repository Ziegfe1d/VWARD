# VWARD Panel

Панель VWARD работает в локальной сети и использует CGI API с того же адреса. Она не
загружает шрифты, иконки или библиотеки из интернета.

## Разделы

Каждым компонентом управляют из его раздела, и там же видно, что он делал: страница
«События» (или строка раздела: «Решения автоподбора», «Сверка маршрутов», «IP-категории
обновлены», «События VPN», «События интернета», «Последняя проверка» обновлений, «Последний
сбор» Wi-Fi, «События» рекламы) показывает события простыми словами, свежие сверху, с
цветной точкой (норма, внимание, ошибка); рутинные проверки не показываются, одинаковые
события подряд сворачиваются в одно с числом. На той же странице - действия раздела:
у домена из автоподбора или сверки - «закрепить», «вернуть напрямую», «всегда через VPN» или
«убрать из списка» (по тому, где домен сейчас); «Сверить сейчас», «Обновить IP-категории»,
защита VPN с «Проверить», «Интернет пропал прямо сейчас?», «Проверить обновления»; событие
Wi-Fi открывает устройство, событие рекламы - страницу, где это настраивается. Сырые
журналы - «Технические журналы» (меню «Ещё» и «Система» → «Диагностика»), только для
диагностики и отправки.

- «Обзор»: карточки разделов; значок с треугольником появляется только при проблеме.
- «Интернет»: «Восстановление интернета» (включение, как часто проверять, «Дополнительно» -
  параметры и история) и «Интернет пропал прямо сейчас?» (обновить адрес, переподключить).
- «VPN»: туннели, их состояние, замена конфигурации, туннель для маршрутов.
  Новый туннель: файл `.conf`, ввод вручную или ключ Amnezia `vpn://` своего сервера (разбирается
  в браузере; ключ Amnezia Premium туннеля не содержит - форма так и говорит).
- «Доменные списки»: списки Keenetic, у каждого своя страница (обход, наблюдение, домены,
  исключения); Smart DNS.
- «Маршрутизация»: «Автоподбор доменов» (группа `AdaptiveAuto`), мои домены, IP-категории.
  «Источники» - откуда берутся данные, что из них берётся и зачем, когда каждый обновлялся и
  сколько дал (`sources` в `route-data`, файл `/opt/var/lib/vward/route-sources.status`):
  itdog (домены и подсети), v2fly, Re:filter community (сервисы, не пускающие пользователей из
  РФ), antifilter community, Loyalsoldier geoip, официальные подсети сервисов (Telegram).
  Источники только подсказывают: домен уходит в VPN после проверки на провайдере пользователя.
  Не скачавшийся источник работает прошлой копией и отмечен в Панели VWARD.
  «Мои домены» - одна из групп Keenetic, идущих через туннель. Когда таких групп несколько
  (например, списки Telegram и YouTube), VWARD сам не выбирает: в «Сводке» и на странице «Мои
  домены» появляется выбор «Мои домены добавляются в» (`config` `op=policy-group`, выбор
  записывается в `device.conf` как `VWARD_POLICY_GROUP`). Категории доменов и проверяемые
  сервисы без своих файлов (`categories.tsv`, `services.conf`) показаны как «не настроены».
- «Wi-Fi клиенты»: устройства, диапазон для устройства, причины переподключений.
- «Реклама и трекеры»: только работа VWARD - проверка доменов, публикация правил, источники;
  внизу «Дополнительно» → «AdGuard Home» в «Утилитах».
- «Утилиты»: программы, с которыми работает VWARD. «AdGuard Home» (`/utilities/adguard-home`):
  веб-интерфейс, подключение, его настройки и фильтры, «Защита для всех устройств», имена
  устройств из Keenetic, «Домены маршрутов через DNS Keenetic», версия (ведёт в «Обновления»).
- «Система»: устройство, компоненты, диагностика, файлы, хранилище.
- «Обновления»: VWARD, AdGuard Home, прошивка Keenetic и пакеты Entware, у каждого своя
  страница (см. ниже).
- «Настройки»: тема, вход в Панель VWARD, резервные копии.
- «Технические журналы»: сырые журналы с копированием, сохранением и автообновлением; на
  нижнюю панель по умолчанию не выводятся.

## Что можно изменять

API принимает POST только с заголовком `X-VWARD-Request: console`, ограничивает body,
проверяет все значения и блокирует запись во время updater transaction.

- `settings`: `auto_apply`, `auto_critical`, `auto_important`, `auto_routine` в `update.conf`.
- `config` (текущие значения - `config-data`) передаёт изменение в
  `/opt/bin/vward-console-config.sh`, единственный путь записи настроек из Панели VWARD:

| op | Что меняет | Где хранится |
| --- | --- | --- |
| `route-domain add/remove` | «Мои домены» через VPN | FQDN-группа `VWARD_POLICY_GROUP` в Keenetic |
| `force-vpn add/remove` | «Всегда через VPN» | `/opt/etc/vward/route-engine/force-vpn.conf` |
| `adaptive pin/remove` | закрепить домен в «Моих доменах» или вернуть напрямую | группа `AdaptiveAuto`, `adaptive-persist.txt`, `adaptive-domains.txt` |
| `domain-category ID 0/1` | категория доменов | `/opt/etc/vward/route-engine/categories.tsv` |
| `tunnel-guard 0/1` | Защита VPN (выключение - токен `TUNNEL_GUARD_DISABLE`) | `/opt/etc/vward/tunnel-guard.disabled` |
| `wifi KEY VALUE` | `ENABLED`, `CONTROL_ENABLED` (включение - токен `WIFI_CONTROL_ENABLE`), `WINDOW_SEC`, `BAND_SWITCH_WARN`, `WEAK_5G_SAMPLE_WARN`, `WEAK_5G_RSSI` | `/opt/etc/vward/wifi-client-guard.conf` |
| `update KEY VALUE` | `safe_window_start`, `safe_window_end`, `check_interval_seconds` | `/opt/etc/vward/update.conf` |
| `wan-guard 0/1` | Защита интернета (выключение - токен `WAN_GUARD_DISABLE`) | `/opt/etc/vward/wan-guard.disabled` |
| `component ID 0/1` | компонент включён (выключение - токен `COMPONENT_DISABLE`) | `/opt/etc/vward/components/<id>.disabled` |
| `update apply_window window/any` | «По расписанию» / «Автоматически» (вместе с `auto_apply` через `settings`) | `/opt/etc/vward/update.conf` |
| `update-feed beta/dev` | канал: ветка подписанного feed (Dev - токен `UPDATE_FEED_DEV`) | `manifest_url` в `update.conf` |
| `adaptive-mode 0/1` | «Автоподбор доменов» добавляет новые домены | `/opt/etc/vward/route-engine/adaptive.disabled` |
| `classifier 0/1` | автоопределение категории новых доменов | `CLASSIFIER_ENABLED` в `domain-classifier.conf` |
| `ip-category NAME 0/1` | IP-категория может получать маршруты | `/opt/etc/vward/policy-sync/excluded.categories` |
| `console-auth 0/1` | вход по учётной записи Keenetic (только через `auth`) | `/opt/etc/vward/console/auth.conf` |
| `tunnel NAME` | туннель для маршрутов (токен `TUNNEL_SWITCH`) | DNS-маршруты групп в Keenetic, `/opt/etc/vward/device.conf` |

Helper принимает только перечисленные ключи и строгие значения (домен - только буквы, цифры,
дефис и точки; числа - в пределах, без ведущих нулей; время - `ЧЧ:ММ`, начало окна не равно
концу), работает в runtime admission, делает резервную копию в
`/opt/var/backups/vward/console-config` (последние 20 на файл), пишет файл атомарно с
сохранением прав и проверяет результат. Группы Keenetic меняются под общей блокировкой
`/tmp/vward-route-change.lock`; если Keenetic отклонил команду или результат не
подтвердился по `show running-config`, изменение откатывается. После изменения групп
выполняется `system configuration save`, а движок маршрутизации перечитывает группы. Каждое
изменение записывается в `/opt/var/log/vward/console-audit.log` (`CONSOLE_CONFIG`).

Переключение туннеля (`tunnel`) принимает только WireGuard-интерфейс из карты устройства и
не выполняется, пока активен fail-open или идёт policy-sync. Под блокировкой маршрутов и
policy-sync оно:

1. добавляет маршрут `route object-group` к новому туннелю для группы «Моих доменов» и
   `AdaptiveAuto` (в том же контексте `dns-proxy` и с теми же опциями `auto`/`reject`, в той же
   форме имени - логической или системной), затем снимает маршрут к старому туннелю; другие
   группы не трогает;
2. проверяет результат по `show running-config`;
3. записывает в `device.conf` `VWARD_TUNNEL_INTERFACE`, `VWARD_TUNNEL_DEVICE` и закрепляет
   `VWARD_POLICY_GROUP`, после чего профиль устройства должен загрузиться с новыми значениями;
4. сохраняет конфигурацию роутера.

Любая ошибка на этих шагах (и сигнал) откатывает выполненные шаги в обратном порядке; если
откат не удался целиком, ответ - `rollback_incomplete`. После успеха сбрасывается состояние
Защиты VPN, перезапускается движок маршрутизации и в фоне запускается
`vward-policy-sync.sh --reconcile`: policy-sync помнит устройство своих IP-маршрутов
(`owned.interface`), снимает их со старого туннеля и добавляет через новый; маршруты, которые
не удалось снять, остаются за старым устройством и повторяются при следующем запуске.

Точный синтаксис `dns-proxy route object-group` / `dns-proxy no route object-group`
нужно один раз проверить на роутере: неверная форма команды не меняет маршрутизацию
(отказ или откат по проверке), но переключение не выполнится.

### Реклама и трекеры

- `ads-view` (GET, только чтение, `vward-ads-privacy-view.sh`): `querylog` - журнал запросов
  AdGuard Home с фильтром (все / заблокированные / разрешённые / на проверке) и поиском по части
  домена; `stats` - счётчики AdGuard Home за сутки; `list review|blocked` - домены на проверке и
  заблокированные VWARD (из `verdicts.tsv`); `publish-status` - правила, отличающиеся от
  опубликованных (публикация сохраняет `published.rules`).
- «Защита для всех устройств»: «Все устройства через AdGuard Home» (любой DNS-запрос из
  домашней сети отвечает AdGuard Home) и «Не давать обходить защиту» (закрыты DoT/DoQ,
  известные адреса DoH и имена DoH через список HaGeZi), «Исключения» по устройствам
  (`ads-control` `op=dns-guard setting=enforce|bypass|exclude`, состояние - `dns_guard` в
  `ads-data`). Пока выход AdGuard Home в интернет не зашифрован, включить нельзя.
- Имена устройств: в блоке AdGuard Home переключатель «Имена устройств из Keenetic» и кнопка
  «Обновить имена» (`ads-control` `op=clients value=on|off|sync`, состояние - `clients` в
  `ads-data`). VWARD записывает имена зарегистрированных устройств в клиенты AdGuard Home через
  его API, без перезапуска. Пока в cron стоит старый `agh-keenetic-clients-sync.sh`, VWARD ждёт
  и показывает предупреждение.
- «Домены маршрутов через DNS Keenetic» на странице AdGuard Home в «Утилитах» (`ads-control` `op=route-dns
  value=on|off`, состояние - `route_dns` в `ads-data`): домены из групп Keenetic с маршрутом
  AdGuard Home отправляет в DNS Keenetic, и маршрут сразу знает адреса, которые получило
  устройство, включая поддомены. Экспериментально и выключено по умолчанию (флаг
  `route-dns.enabled`): на роутере владельца DNS Keenetic принял цепочку за петлю («proxy loop
  detected: 192.168.1.1 <-> 192.168.1.1»), отключил AdGuard Home и потерял свой DNS. Если DNS
  Keenetic перестаёт отвечать, пока функция включена, VWARD сам её выключает (`dns_lost`).
  Работает, только когда DNS Keenetic сам спрашивает AdGuard Home.
- `ads-control`: кроме правил и режимов источников - `source-add` (свой список по https: адрес
  без логина и пробелов, формат `adblock`/`hosts`/`domains`, до 10 списков, старт в режиме
  «Проверка»; размер до 8 МБ и не меньше 10 записей проверяются при загрузке),
  `source-delete` (только свои), `source-category` (все источники категории выключаются или
  возвращаются в режим по умолчанию). Свои источники хранятся в `custom-sources.json` и
  собираются в реестр только из проверенных полей; встроенный источник они не заменяют.

### Задания по расписанию

`cron-data` читает установленный crontab (`/opt/var/spool/cron/crontabs/root`) и файлы
`/tmp/<задание>.cron.last|rc`: расписание, последний запуск, код возврата и компонент
каждого задания. `control` `housekeeping` сжимает журналы больше лимита (две копии).

### Вход в Панель VWARD

Выключен по умолчанию (`auth.conf`, `AUTH_ENABLED=0`). Когда включён, все действия API, кроме
`auth` и `ping`, требуют сессию: без неё ответ `401 auth_required`, а Панель VWARD показывает форму
входа. Пароль проверяет роутер по схеме Keenetic: `GET /auth` даёт `X-NDM-Realm` и
`X-NDM-Challenge`, VWARD отправляет `sha256(challenge + md5(login:realm:password))`; пароль
не записывается на диск и не попадает в аргументы процессов. Сессия - случайный токен в cookie
`HttpOnly; SameSite=Strict`, на диске (`/tmp/vward-console-sessions`) только его sha256 и срок
(`SESSION_HOURS`, 12 ч). После 5 неверных попыток за 5 минут вход блокируется на 5 минут.
Включение требует рабочих логина и пароля, выключение - сессии и подтверждения
`CONSOLE_AUTH_DISABLE`. Оболочка страницы без данных отдаётся lighttpd напрямую.

### Имя, по которому открыт VWARD

API отвечает только на запросы к IP-адресу роутера, `localhost`, однословным и локальным
именам (`*.local`, `*.lan`, `*.home`, `*.home.arpa`, `*.internal`), `my.keenetic.net` и облачным
именам Keenetic; на остальные - `403 host_not_allowed`. Так страница чужого сайта, чьё имя
злоумышленник направил на роутер (DNS rebinding), не может управлять VWARD, даже когда вход
выключен. Свои имена добавляются в `auth.conf` строкой `ALLOWED_HOSTS=имя1 имя2`
(маленькими буквами); `HOST_CHECK=0` отключает проверку.

### Резервные копии

Копия на роутере (`/opt/var/backups/vward/snapshots`, только root, последние 7) содержит всё
для восстановления, включая ключи туннелей и вход AdGuard Home. Скачанный через Панель VWARD файл
собирается из неё без секретов: без хранилища туннелей, `*.auth`, `*.key`, CA HTTPS-фильтра и
конфигурации роутера (`backup.meta`: `secrets_removed=1`).

### Обновления

Раздел собирает всё, что можно обновить, как в веб-интерфейсе Keenetic: список, у каждого
пункта своя страница с версией, доступной версией, переключателем «Обновлять автоматически»
и, где есть, каналом.

- **VWARD** - прежние настройки обновлений VWARD (режим, время, канал) и «Что нового».
- **AdGuard Home** - установлен пакетом Entware `adguardhome-go`, его самообновление выключено,
  поэтому обновляет opkg.
- **Пакеты Entware** - пакеты, для которых `opkg list-upgradable` нашёл новую версию. Системные
  (`libc`, `busybox`, `opkg`, `dropbear` и др.) - только вручную и со вторым подтверждением.
- **Прошивка Keenetic** - версия и состояние из `components check-update` (RCI). Меняются только
  настройки самого Keenetic: `components auto-update enable|disable` и
  `components auto-update channel stable|preview|draft`; тестовые каналы - с подтверждением.
  Прошивку устанавливает Keenetic: при установке роутер перезагружается.

Установка пакета (`vward-console-config.sh ext-upgrade`): только из списка последней проверки,
при свободных 20 МБ; до установки копируются файлы пакета и его зависимостей, которые opkg
обновит, и база opkg (`/opt/var/backups/vward/ext-update`, последние 3). После установки
перезапускаются включённые службы пакета и повторяются проверки jq, curl, DNS через AdGuard Home
и ответ Панели VWARD. Если проверка, прошедшая до установки, после неё не проходит (ждём до 30 с),
файлы и база возвращаются. Одна операция за раз (`/opt/var/lib/vward/ext-update/lock`).

Проверка (`ext-check`): `opkg update`, список обновлений и состояние прошивки. Сама запускается
раз в сутки из обслуживания, в час установки обновлений VWARD; первая - в течение часа после установки.
В этот же запуск (`ext-daily`) ставятся обновления, для которых включено «Обновлять
автоматически»: AdGuard Home и несистемные пакеты Entware. Настройки -
`/opt/etc/vward/ext-update.conf` (`AGH_AUTO`, `ENTWARE_AUTO`), по умолчанию выключены.

### Компоненты

Граф берётся из `component-registry.json` (в Панели VWARD - через `config-data`):

- `depends_on` - компонент использует файлы другого (проверяется и установщиком обновлений);
- `requires_running` - компонент не может работать без другого: при выключении зависимого
  компонента он выключается вместе с ним, при включении - включает его;
- `uses` - мягкая связь: компонент продолжит работать на последних данных другого;
- `core` - Ядро платформы, Среда выполнения, Панель VWARD и Обновления; выключить нельзя.

Выключенный компонент остаётся установленным: файлы, настройки и проверки здоровья
обновлений не меняются. Его точки входа (cron, supervisor, `S91vward-route-engine`, ручные
инструменты) проверяют `vward_component_gate` и завершаются без действий
(`COMPONENT_DISABLED=<id>`); движок маршрутизации останавливается сразу. Ручные действия
Панели VWARD для выключенного компонента возвращают `component_disabled`. Защита VPN не
выключается, пока активен fail-open. Выключение Блокировки рекламы не снимает уже
опубликованные в AdGuard Home правила, выключение IP-категорий не удаляет уже созданные
маршруты - они перестают обновляться.

WAN доступен только для чтения. `route-data` читает только
фиксированные generated/state paths VWARD и не принимает path или команду от frontend.
API не принимает произвольные shell-команды, paths или команды `ndmc`.

## Журналы

Разрешены только имена `wan`, `recovery`, `cron`, `routing`, `adaptive`, `updater`,
`tunnel`, `policy`, `policysync`, `console`, `wifi`, `ads` (до 1000 последних строк). Каждое имя жёстко связано со своим файлом в `api.cgi`.
Произвольный path передать нельзя. Панель VWARD может одновременно загрузить несколько
разрешённых источников, отфильтровать текущий вид по поиску, скопировать его, сохранить
в TXT или передать через системный Web Share API. Автообновление выполняется только
пока открыт раздел журналов. Содержимое может включать локальные домены, поэтому перед
публикацией его всё равно нужно проверять.

## Проверка после установки

1. Открыть каждый пункт бокового и нижнего меню.
2. Открыть каждую карточку Overview и вернуться назад.
3. Проверить все восемь источников журналов, множественный выбор, поиск, копирование, сохранение, Share и автообновление.
4. Обновить данные и убедиться, что ошибок API нет.
5. Проверить светлую и тёмную темы.
6. Проверить 320, 360, 768 и 1440 CSS px, portrait и landscape.
7. Увеличить масштаб до 200% и проверить keyboard focus.
8. Изменение updater-флагов проверять только в контролируемом окне с backup.

Source tests не заменяют проверку установленной Панели VWARD. Если source и runtime hashes
различаются, сначала нужно определить установленный package/slot и причину расхождения.

## Control plane: безопасные ручные операции

Исходный код Панели VWARD поддерживает четыре явных API-направления: `diagnostics`, `route-probe`,
`control` и `update-control`. Ни одно из них не принимает shell-команду, path или `ndmc`
строку от браузера. `route-probe` принимает только валидированный домен или IPv4 и
сопоставляет его с локальными каталогами/state и фиксированным снимком running-config.

Разрешённые component actions: обновление доменных hints, запуск Route Reconciler,
обновление/сверка Policy Sync, health probe Tunnel Guard, «Обновить адрес» (`wan-renew`,
токен `WAN_RENEW`) и «Переподключить» (`wan-bounce`, токен `WAN_BOUNCE`). Операции, способные менять
маршруты, требуют отдельного server-side confirmation token. Одновременно выполняется
только одно действие Панели VWARD; при активной updater transaction component actions
блокируются. Результат и RC попадают в журнал аудита Панели VWARD без секретов.

VWARD Update Engine вызывается только штатными флагами `--check`, `--apply-pending`,
`--rollback` и `--recover`. Apply/retry/rollback/recovery требуют отдельного
подтверждения. Signature/trust/sequence проверки остаются внутри Update Engine и через
Панель VWARD не отключаются.

VWARD WAN Guard намеренно не запускается принудительно из Панели VWARD под видом простой
проверки: его рабочий цикл способен инициировать recovery. Кнопка «Проверить» обновляет
только read-only RCI/status. Ручные действия выполняет отдельный
`vward-wan-recovery.sh` (`dhcp-renew` / `wan-bounce`) для интерфейса из профиля устройства:
он берёт ту же блокировку, что WAN Guard, перед отключением записывает маркер владения
(незавершённое переподключение поднимает сам инструмент по сигналу или следующий запуск
WAN Guard) и допускает не больше одного ручного действия в минуту. Ручные действия не
расходуют лимиты автоматического восстановления и пишутся в журнал восстановлений.

Выключенная Защита интернета (`wan-guard.disabled`) продолжает раз в минуту проверять и
журналировать связь, но не обновляет адрес и не переподключает интерфейс
(`ACTION=DISABLED_BY_USER`); счётчики неудач при этом не накапливаются. Незавершённое
переподключение восстанавливается и в выключенном состоянии.

## Диагностика

`diagnostics` выполняет только фиксированный набор read-only проверок: `/opt`, основные
зависимости, `crond`, supervisor, AdGuard Home, «Автоподбор доменов», WAN, WireGuard, lighttpd,
активный Update Engine slot и update config. Ответ возвращает `PASS/WARN/FAIL/UNKNOWN`
с короткой причиной. Произвольные команды и произвольные файлы недоступны.

## Единый каталог настроек и доступность Update Engine actions

`config/settings/settings-registry.json` является единым описанием доступных Панели VWARD
параметров. Для каждого параметра заданы component, section, русские название и
описание, source/key, тип, допустимые границы, editable/secret, restart requirement,
risk и причина read-only.

Раздел Settings различает три типа значений: `READ ONLY` для фактического состояния
роутера, `EDITABLE` для четырёх разрешённых параметров VWARD Update Engine и `LOCAL`
для настроек интерфейса/журналов, сохраняемых только в браузере. Есть поиск по
настройкам. Локально настраиваются тема, компактность, минимум анимации, polling
Панель VWARD, интервал автообновления журналов, 50/100/150/200 строк на источник и перенос
длинных строк. Backend жёстко ограничивает log tail диапазоном 20..200.

Параметры `device.conf` не редактируются из браузера до внедрения настоящей
авторизации и двухфазного apply для адреса/порта Панели VWARD. Заголовок
`X-VWARD-Request` остаётся только барьером запросов и не считается аутентификацией.

`update-data` читает только updater state/pending/backup/lock и возвращает набор
разрешённых действий. Панель VWARD скрывает операции, которые сейчас не разрешены.
`update-control` повторяет критические precondition checks server-side: apply требует
pending manifest и допустимую фазу, rollback требует валидный recorded backup, recovery
показывается только для прерванных transaction phases. Окончательные trust/signature/
sequence/compatibility проверки остаются внутри VWARD Update Engine.

## Финальное закрытие control-plane требований

Журналы имеют явные «Все» и «Сброс». Tunnel Guard показывает selector всех
обнаруженных WireGuard-интерфейсов, но ручной health probe остаётся привязан к
управляемому VWARD-туннелю; остальные интерфейсы read-only, пока нет безопасного
per-tunnel actuator.

Route Engine добавляет локальный фильтр/сортировку ограниченных списков, время
обновления доменных источников, последнюю Policy Sync сверку и её `added/removed`.
`route-probe` поддерживает домен/DNS, IPv4 и точную FQDN-группу. Групповой probe
возвращает не более 100 участников и назначенные интерфейсы маршрутов.

Текущий автоподбор доменов не сохраняет отдельный структурированный lifecycle для очереди
`discovered/pending/processing/excluded/error`; Панель VWARD намеренно не синтезирует такие
счётчики из логов. Они появятся только после добавления authoritative runtime state.
Также нет отдельного безопасного «обновить один компонент»: VWARD Update Engine
устанавливает подписанный component-aware package как одну транзакцию. Панель VWARD не
обходит эту модель.
