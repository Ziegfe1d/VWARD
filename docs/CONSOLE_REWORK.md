# VWARD Console: список доработок

Рабочий список изменений интерфейса Console по итогам просмотра демо-страницы.
Отмечаем выполненное прямо здесь.

## Правило для всех этапов

Изменение интерфейса правит существующий код, а не дописывает поверх. Новое CSS-правило
заменяет старое; одно и то же свойство одного элемента задаётся в одном месте.

## Структура разделов

У каждого параметра одно место и одно имя; поиск ведёт прямо к нему.

| Группа | Раздел | Что там |
|---|---|---|
| Главное | Обзор | карточки состояния, настраиваемые |
| Главное | Журналы | все журналы, экспорт |
| Сеть | Интернет | подключение, интерфейс, проверка связи |
| Сеть | VPN | туннели, fail-open |
| Сеть | Маршрутизация | каталог, AdaptiveAuto, группа маршрутизации, проверка адреса |
| Сеть | Wi-Fi клиенты | сбор данных, домашний сегмент, клиенты |
| Сеть | Реклама и трекеры | AdGuard Home, блокировки, источники |
| VWARD | Система | устройство, компоненты, среда выполнения, хранилище |
| VWARD | Обновления | состояние и все настройки обновлений |
| VWARD | Настройки | доступ к Console и вход, нижняя панель |

- «Безопасность» объединена с «Настройками»: вход по паролю задаётся в одном месте.
- Сведения об устройстве и автоматически найденные интерфейсы показаны в своих разделах,
  а не отдельным блоком «только чтение» в «Настройках».
- Тема переключается одной кнопкой в шапке, без дубля в «Настройках».
- Одно имя для одного понятия: «Интернет» вместо смеси «Интернет»/«WAN»; «Система» вместо
  «Платформа»; компоненты названы по-русски и не совпадают с названиями разделов
  («Движок маршрутизации», «Защита интернета», «Контроль Wi-Fi клиентов»).
- Кнопка «Журнал» в карточке компонента открывает нужную вкладку журналов.

## Этап 1. Основа: чистый CSS

- [ ] Свести `vward-console.css` к одному набору правил без многослойных переопределений
      (сейчас, например, у кнопок нижней панели около 10 перекрывающих правил).
- [ ] Единые токены: цвета светлой и тёмной темы, шрифты, размеры, отступы, радиусы, тени.
- [ ] Проверить выравнивание текста, шрифты, анимации, переходы, заливки, линии; убрать
      наслоения текста.
- [ ] Регрессионная проверка: одно свойство одного селектора не переопределяется повторно.

## Этап 2. Иконки

- [ ] Перерисовать все иконки в едином формате и стиле: одна сетка, толщина линии,
      скругления (обновление, тема, уведомления, поиск, навигация, действия).

## Этап 3. Шапка и навигация

- [ ] Убрать синий блок статуса на главном экране.
- [ ] Колокольчик уведомлений справа в шапке: спокойный, когда всё в порядке; счётчик
      при неполадках; по нажатию - список проблем со ссылкой на нужный раздел.
- [ ] Общий поиск значком рядом с колокольчиком: ищет по всей Console (разделы, настройки,
      компоненты) и переходит к найденному; убрать поля поиска со страниц.
- [ ] Компактные кнопки шапки на узком экране.
- [ ] Нижняя панель на телефоне: скруглённая «плавающая» форма сохраняется, фон непрозрачный,
      контент не уходит под панель, подписи без обрезки, подложка активного пункта внутри панели.
- [ ] Настройка нижней панели: выбор до 4 разделов и их порядка, остальные - в «Ещё».
- [ ] «Назад к обзору» не уезжает под верх экрана.

## Этап 4. Содержимое страниц

- [ ] Карточки обзора: метки статуса не выходят за край, нет залипающей рамки после
      касания, иконка выровнена по верху с текстом, одинаковое описание на телефоне и
      компьютере, компактная высота.
- [ ] «Настроить карточки» - компактная кнопка или пункт меню, без отдельной строки.
- [ ] Характеристики на всех страницах - компактный список «название - значение» с тонкими
      разделителями вместо сетки плиток; цветная метка только там, где есть состояние.
- [ ] Без вложенности «карточка в карточке в карточке».
- [ ] Понятные русские метки вместо «READ ONLY», «ТОЛЬКО VWARD» и подобных.
- [ ] Любое число, за которым стоит список («3 домена», «214 маршрутов», «11 компонентов»),
      кликабельно и открывает этот список; «назад» в шапке возвращает в раздел.
- [ ] Подсказка под названием параметра объясняет, а не повторяет значение или состояние
      («работает» не пишется и в подсказке, и в значении).
- [ ] Адреса веб-интерфейсов - внешние ссылки: AdGuard Home в «Рекламе», веб-интерфейс
      Keenetic в «Системе» (вернуть кнопку «Keenetic ↗» из старой Console).
- [ ] Значение, которое относится к другому разделу, ведёт в него («Версия VWARD» -
      в «Обновления», «Туннель для маршрутов» - в «VPN»); «Заблокировано запросов» открывает
      журнал запросов сразу с фильтром «Заблокированные».
- [ ] Строки «последнее событие» («Последняя сверка», «Последний сбор», «Последняя проверка»,
      «Проверка туннеля», «Служебная очистка») открывают журнал на нужной вкладке; строки
      «Диагностики» ведут в свой раздел, «Задания по расписанию» - в карточку компонента.
- [ ] Подпись строки не повторяет её метку состояния («не помогло» + «Не помогло»).
- [ ] Журналы: кнопки «Копировать», «Поделиться» (системное меню, где браузер его даёт),
      «Сохранить .txt» и «Все журналы» одним файлом; перенос длинных строк включён по
      умолчанию и переключается; вкладки журналов переносятся, а не уходят за край.
- [ ] Страница не выделяет текст и не показывает меню «Копировать» при долгом нажатии;
      выделение остаётся только в полях ввода и журналах.

## Этап 4а. Настройки обновлений в разделе «Обновления»

- [ ] Прямо на странице один выбор «Установка обновлений»: «Автоматически» (сразу),
      «По расписанию» (в окно «с - до», критические исправления - сразу) или «Вручную»
      (только проверка и уведомление). Окно показывается только для «По расписанию».
- [ ] Там же канал «Бета»/«Dev» с предупреждением про dev и интервал проверки.
- [ ] Изменения применяются кнопкой «Сохранить» с возможностью «Отменить»; неверное окно
      (начало = конец) не сохраняется.
- [ ] Кнопки «Проверить» и «Откатить» одинаковой ширины в одну строку.
- [ ] Бэкенд: режимы на существующих ключах - «Вручную» = `auto_apply=0`; «По расписанию» =
      `auto_apply=1` с окном `safe_window_start/end`; «Автоматически» = `auto_apply=1` без
      ограничения окном (нужна поддержка в Update Engine). Добавить безопасную запись `channel`,
      `safe_window_start/end` и `check_interval_seconds` с проверкой значений и журналом аудита.

## Этап 4б. Реклама и трекеры: полное управление без AdGuard Home

- [ ] Главная страница раздела: переключатель блокировки (пауза/возобновление), состояние
      AdGuard Home, статистика за сутки; ссылки на списки; публикация; проверка домена;
      настройки (режим «По расписанию»/«По запросам», интервал, автообновление источников,
      область новых правил).
- [ ] Журнал запросов с фильтром (все / заблокированные / разрешённые / на проверке) и
      кнопками «Разрешить»/«Заблокировать» у каждой строки.
- [ ] «На проверке»: решение по каждому домену одной кнопкой.
- [ ] «Заблокировано»: поиск и «Разрешить».
- [ ] «Мои правила»: добавить домен (блокировать/разрешить, только домен/с поддоменами),
      удалить правило.
- [ ] «Источники»: режим каждого источника «Выключен / Проверка / Активен»; добавить свой
      источник по https-адресу (сначала в режиме «Проверка»), удалить свой.
- [ ] «Категории блокировки»: переключатели категорий.
- [ ] «Задания»: текущее, очередь, последнее; «Обновить источники», «Пересобрать правила».
- [ ] Публикация в AdGuard Home: счётчик неопубликованных изменений, «Опубликовать» с
      подтверждением на странице, переключатель автопубликации.
- [ ] Строки списков на телефоне: статус цветным словом в подписи, действия иконками,
      домены переносятся только по точкам.
- [ ] Бэкенд: журнал запросов AdGuard Home в Console API; статистика за сутки; запись
      категорий и режима работы; пользовательские источники (сейчас список источников
      фиксирован в `source-registry.json`) с проверкой адреса, размера и формата.

## Этап 4в. VPN и маршрутизация

- [ ] VPN: список туннелей (состояние, handshake, трафик), у каждого - карточка с сервером,
      адресом, MTU; туннель для маршрутов отмечен в подписи.
- [ ] «Использовать для маршрутов» в карточке туннеля с подтверждением на странице
      (с предупреждением, если туннель не в сети).
- [ ] Защита VPN: переключатель, состояние fail-open, частота проверки и восстановления,
      «Проверить» и «Журнал».
- [ ] Маршрутизация: сводка (туннель, домены, маршруты, группа); «Что идёт через VPN» -
      мои домены, «всегда через VPN», AdaptiveAuto, категории доменов, IP-категории,
      проверяемые сервисы; проверка адреса.
- [ ] Мои домены и «Всегда через VPN»: добавить и убрать домен.
- [ ] AdaptiveAuto: закрепить домен в «Мои домены» или убрать.
- [ ] Категории доменов и IP-категории - переключателями, с количеством доменов/сетей.
- [ ] Обслуживание: последняя сверка, «Сверить маршруты» и «Обновить IP-категории» с
      подтверждением на странице.
- [ ] Настройки: AdaptiveAuto вкл/выкл, автоопределение категории новых доменов.
- [ ] Бэкенд: запись `VWARD_TUNNEL_INTERFACE` из Console (сейчас `device.conf` только для
      чтения); включение/выключение Защиты VPN через `tunnel-guard.disabled`; списки
      `manual-domains`, `force-vpn.conf`, AdaptiveAuto (закрепить/убрать), флаги
      `categories.tsv` и активных IP-категорий, `CLASSIFIER_ENABLED` - через Console API с
      проверкой значений и журналом аудита; статистика трафика туннелей из RCI.

## Этап 4г. Интернет, Wi-Fi клиенты, Система, Настройки, Обзор

- [ ] Интернет: подключение (кабель, IPv4, шлюз, DNS), «Проверить» и «Журнал»; Защита
      интернета - переключатель, порядок восстановления по шагам, текущее состояние, история
      восстановлений; «Обновить адрес» и «Переподключить» с подтверждением на странице.
- [ ] Wi-Fi клиенты: переключатели «Сбор данных» и «Ручное управление»; «Автоисправление»
      заблокировано до проверки на роутере; карточка клиента с выбором «Авто / Только 2.4 /
      Только 5 ГГц» (только при включённом ручном управлении) и подтверждением; пороги
      анализа (окно, частые переходы, слабый 5 ГГц, число слабых замеров).
- [ ] Система: устройство и время работы; компоненты, задания по расписанию, диагностика
      (вернуть из старой Console) со ссылками; хранилище и «Очистить временные файлы».
- [ ] Настройки: «Сбросить вид Console» (карточки, нижняя панель, тема в этом браузере).
- [ ] Обзор: карточка «Реклама» - у каждого раздела сети есть карточка.
- [ ] Бэкенд: включение/выключение Защиты интернета (сейчас флага нет); ручные «Обновить
      адрес» и «Переподключить» через Console API с теми же ограничениями частоты, что у
      автоматического восстановления; история восстановлений из журнала; запись `ENABLED`,
      `CONTROL_ENABLED` и порогов Wi-Fi Client Guard; состояние cron-заданий и запуск
      служебной очистки через API.

## Этап 5. Компоненты: карточки и отключение

- [ ] Из списка компонентов - переход в карточку компонента: описание, состояние, версия,
      расписание запуска, журнал, ссылка на раздел, «Зависит от» и «От него зависят».
- [ ] Переключатель «Компонент включён» с подтверждением прямо на странице: перед
      отключением показать, какие компоненты остановятся вместе с ним.
- [ ] Базовые компоненты (Ядро платформы, Среда выполнения, Console, Обновления) отключить
      нельзя - с объяснением причины.
- [ ] Бэкенд: механизм включения/отключения компонента (сейчас его нет, кроме `ENABLED`
      у Wi-Fi Client Guard и Ads Guard): cron, init-скрипты и Console API.
- [ ] Бэкенд: полный граф зависимостей в `component-registry.json` (сейчас указано только
      4 зависимости; фактически почти все компоненты зависят от Среды выполнения и Device Profile).
- [ ] Тест устойчивости: отключение каждого компонента по очереди не ломает остальные -
      их проверки здоровья проходят, cron и Console работают.

## Этап 6. Вход в Console

- [ ] Логин и пароль те же, что у веб-интерфейса Keenetic; проверка через штатную
      авторизацию роутера (`/auth`), пароль в VWARD не хранится.
- [ ] Сессия с ограниченным сроком; без входа закрыты страница и API.
- [ ] Включается настройкой; на время разработки по умолчанию выключено.
- [ ] Формат ответа `/auth` проверить на реальном роутере.

## Приёмка каждого этапа

- ширина экрана от 320 до 1440 px, светлая и тёмная тема;
- нет наложений, обрезанного текста и горизонтальной прокрутки;
- браузерная проверка без ошибок JavaScript;
- тесты репозитория проходят; демо-страница обновлена для просмотра.

Автоматический аудит интерфейса (обход в браузере, как для макета):

- у каждого `data-act` есть обработчик, у каждого обработчика - кнопка; каждая форма
  обрабатывается; каждый `$('id')` существует;
- каждая страница и страница-список достижима из меню; нет переходов на несуществующие страницы;
- «назад» со страницы-списка ведёт в её раздел; каждая запись поиска находит свою строку;
- все кнопки нажимаются без ошибок; Esc закрывает всплывающие панели;
- нет повторяющихся `id`; у кнопок-иконок есть подпись; `role="button"` доступен с клавиатуры
  и срабатывает на Enter и пробел; нет кнопок внутри кнопок;
- заголовок панели не повторяет заголовок страницы; один параметр показан на одной странице.
