================================================================================
СТАНДАРТ КОМАНД ДЛЯ TERMIUS / KEENETIC — v2.3.3
Для любой модели/агента. Применяется ко всем shell-командам, которые
пользователь вставляет в Termius (в т.ч. мобильные сессии) на роутере Keenetic.
Уровни: MUST — обязательно, SHOULD — по умолчанию, MAY — по необходимости.
Изменения относительно v2.2: см. раздел 11.
================================================================================

1. ЦЕЛЬ И ФОРМАТ
1.1 MUST: команда готова к вставке без ручных правок, многострочный блок,
    не одна нечитаемая строка.
1.2 MUST: первая строка — clear.
1.3 MUST: весь блок (кроме clear) выполняется в подоболочке ( ... ).
    Причина: exit в trap иначе закрывает SSH-сессию, а trap остаётся висеть
    в интерактивной оболочке после завершения.
1.4 MUST: пояснение к команде: "Команда только диагностическая, ничего не
    изменяет." или список изменений (см. раздел 8).

1.5 MUST (мобильная вставка): каждая строка не длиннее 60 символов; длинные
    команды переносить ТОЛЬКО с | или \ в КОНЦЕ строки. Строка, начинающаяся
    с | или &&, запрещена: Termius рвёт длинные строки при вставке, и такая
    строка даёт синтаксическую ошибку (оболочка зависает в режиме ">").
1.6 MUST: в теле команды только ASCII (комментарии, echo-заголовки). Кириллица
    удваивает размер и ломает счёт байт при вставке.
1.7 MUST: одна вставка не больше ~1.5 КБ. Больше — писать скрипт в файл
    частями: вставка 1: cat > /tmp/x.sh <<'EOF' ... EOF; вставка 2:
    cat >> /tmp/x.sh <<'EOF' ... EOF и в конце sh -n /tmp/x.sh && sh /tmp/x.sh.
    Когда команда запускается как файл (sh /tmp/x.sh), подоболочка ( ) из п. 1.3
    не нужна: exit закрывает только дочерний процесс.
1.8 MUST: если оболочка зависла на ">", выйти по Ctrl+C и не вставлять заново
    тот же блок.

2. ФАЙЛЫ ВЫВОДА
2.1 MUST: $OUT="/tmp/<префикс>-$(date +%Y%m%d-%H%M%S).txt".
    Префиксы: vward-*, agh-*, router-*.
2.2 MUST: два указателя: ln -sfn "$OUT" /tmp/last_result.txt (общий) и
    ln -sfn "$OUT" /tmp/last_<префикс>.txt (по префиксу, не затирается другими).
2.3 MUST: ротация. /tmp в KeeneticOS — это RAM, на Viva свободно ~13–25 МБ.
    Хранить не более 5 файлов каждого префикса:
    ls -1t /tmp/<префикс>-*.txt | tail -n +5 | while read -r F; do rm -f "$F"; done
    (выполнять до создания нового $OUT). Больше ничего в /tmp не удалять.
2.4 MUST: $OUT хранит сырой вывод (с кодами), чистится только поток для буфера.

3. ПЕРЕХВАТ СИГНАЛОВ
3.1 MUST: trap on_abort INT TERM HUP внутри подоболочки.
3.2 MUST: on_abort: trap '' INT TERM HUP; send_out; строка
    "[ ABORTED / DISCONNECTED ]: PARTIAL RESULT SAVED TO /tmp/last_result.txt";
    exit 130 (выход только из подоболочки).
3.3 NOTE: доставка OSC52 из trap — best-effort; гарантия — файл $OUT.

4. ВЫГРУЗКА В БУФЕР (OSC52)
4.1 MUST: функция send_out:
    ESC=$(printf '\033')
    sed "s/${ESC}\[[0-9;?]*[a-zA-Z]//g" "$OUT" | tail -c "$MAXB" | base64 \
      | tr -d '\r\n' | { read -r B; printf '\033]52;c;%s\a' "$B"; }
    Единый regex для ANSI (включая ESC[?25h). Варианты без \[ запрещены:
    в v2.2 фильтр в trap не удалял коды вообще.
4.2 MUST: MAXB=30000 байт; в буфер уходят последние MAXB байт (итоги в конце).
    Если файл больше — вывести [ WARNING ] size=... и сколько отправлено.
4.3 MUST: sed вызывать без абсолютного пути (/bin/sed в KeeneticOS нет).
4.4 SHOULD: финальная строка "RESULT SENT (OSC52)" (терминал может не принять
    OSC52, поэтому слово COPIED не гарантия) и строка "RAW: /tmp/last_result.txt".
4.5 Запрещено использовать сырые непечатные символы в теле команд.

5. ОСНОВНОЙ БЛОК
5.1 MUST: { ... } 2>&1 | tee "$OUT".
5.2 MUST: шапка: название, дата, release прошивки (ndmc -c "show version"
    | grep -E 'release|title|device'), если ndmc есть.
5.3 MUST: статусы: [ PASS ] [ FAIL ] [ OK ] [ WARNING ] [ NOT_FOUND ] [ SKIPPED ].
5.4 MUST: после блока строка SUMMARY: pass=N ok=N warn=N fail=N
    (счётчики по grep из $OUT, так как переменные из pipe-блока недоступны).
5.5 SHOULD: длинные списки сворачивать (head -n 15, tail -n 10, wc -l),
    оставлять значимое: SUMMARY:, RC=, FAIL, ERROR.

6. ТАЙМАУТЫ И НАГРУЗКА
6.1 MUST: апплета timeout в KeeneticOS BusyBox НЕТ (проверено на Viva,
    5.01.C.8.0-2). Использовать собственную функцию tmo:
    tmo() {
      _ts=$1; shift
      "$@" & _tp=$!
      ( sleep "$_ts"; kill "$_tp" 2>/dev/null ) & _tw=$!
      wait "$_tp"; _tr=$?
      kill "$_tw" 2>/dev/null
      return $_tr
    }
    Внутренние переменные ТОЛЬКО с префиксом _t: в v2.3.2 имена S/P/W/R
    затирали переменные вызывающего скрипта (найдено тестом).
    Вызов: tmo 10 curl ... || echo "[ FAIL ]". Обрыв по лимиту даёт RC=143.
    RC=127 означает "команда не найдена" и не считается успехом.
6.2 MUST: запрещён слепой опрос сотен хостов; --dry-run, --limit 5, выборка.
6.3 MUST: на роутере с MemAvailable < 20 МБ тяжёлые операции не запускать
    ([ SKIPPED ]). Если MemAvailable нет в /proc/meminfo — MemFree+Buffers+Cached.

7. LOCK (если скрипт делит ресурсы с cron)
7.1 MUST: lock-каталог с pid; если pid жив — [ SKIPPED ] busy; если мёртв —
    удалить lock и продолжить (stale lock).
    LOCK="/tmp/<имя>.lock"
    if [ -d "$LOCK" ] && kill -0 "$(cat "$LOCK/pid" 2>/dev/null)" 2>/dev/null; then
      echo "[ SKIPPED ] busy"; exit 0
    fi
    rm -rf "$LOCK"; mkdir "$LOCK" && echo $$ > "$LOCK/pid"
    (снять lock при завершении)

8. КОМАНДЫ С ИЗМЕНЕНИЯМИ
8.1 MUST: backup cp target target.bak.$(date +%s); правка через *.tmp;
    валидация перед заменой; откат (rollback); итоговый статус.
8.2 MUST: ndmc -c "system configuration save" ДО любого up/down/restart
    интерфейсов (Wi-Fi/VPN/OpkgTun), иначе обрыв SSH потеряет конфиг.
8.3 MUST: перед патчем — наличие файла и sha256sum; маркер для sed ровно 1 раз;
    синтаксис через sh -n (BusyBox ash); сначала диагностика причины, патчи не вслепую.
8.4 MUST: awk/sed/grep-патч сначала тестируется в subshell на краевых случаях
    (пустые строки, targets=0), только потом запись в файл.
8.5 MUST: не писать "проверено", пока не пройден acceptance на роутере.

9. ПРОВЕРКА ПЕРЕД ОТПРАВКОЙ (чек-лист для автора команды)
    [ ] парность кавычек и скобок, if/fi, for/done, case/esac, heredoc
    [ ] sh -n прошёл (dash или busybox ash)
    [ ] блок не оставляет shell в режиме ожидания ввода (>)
    [ ] нет exit вне подоболочки, trap внутри подоболочки
    [ ] ANSI regex единый (п. 4.1), MAXB задан, ротация есть
    [ ] нет команд, меняющих систему, если заявлена диагностика

10. АВАРИЙНОЕ ИЗВЛЕЧЕНИЕ (RECALL)
    Повторный запуск после обрыва запрещён. В новой сессии:
    ESC=$(printf '\033'); [ -s /tmp/last_result.txt ] && sed "s/${ESC}\[[0-9;?]*[a-zA-Z]//g" /tmp/last_result.txt | tail -c 30000 | base64 | tr -d '\r\n' | { read -r B; printf '\033]52;c;%s\a' "$B"; } && echo "LAST RESULT RECOPIED"

11. ЧТО ИЗМЕНЕНО В v2.3 (от v2.2)
    - исправлен ANSI-regex (в trap не работал; ESC[?25h не удалялся);
    - блок в подоболочке: Ctrl+C не закрывает SSH, trap не остаётся в сессии;
    - ротация файлов (RAM) вместо "не удалять никогда"; указатель по префиксу;
    - лимит буфера: последние MAXB байт, а не обрезка начала;
    - SUMMARY, release прошивки в шапке, RC=124/143, OSC52-честное сообщение;
    - lock со stale-проверкой; закомментированы метки [1][2][3] шаблона;
    - убрана привязка к конкретной модели ("for Gemini").
    v2.3.3: tmo не затирает переменные вызывающего скрипта (_t-префикс).
    v2.3.2: timeout отсутствует на Keenetic -> функция tmo (п. 6.1);
    OSC52 в Termius подтверждён на роутере.
    v2.3.1: правила мобильной вставки (п. 1.5–1.8): короткие строки, ASCII,
    куски до ~1.5 КБ, запуск файлом. Причина: сбой вставки 4 КБ-блока в Termius.
