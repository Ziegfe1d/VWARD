# P-7 и архитектура B: безопасная интеграция

P-7 `5869f119f6f8c43f001d80c2d6d9da3c24daf9ec` и защитный стек
B `aee436c625b53bbbb091f7bb6385b7946fe6a6e2` пока проверялись раздельно.
Прежний read-only merge-tree подтвердил конфликты console-config.sh,
SHA256SUMS, docs/AGENT.md и docs/ROADMAP.md. Наличие зелёного CI у каждого
стека не доказывает совместимость. Новые пакеты здесь P-7 не импортируют.

## Порядок отдельного интеграционного пакета

1. Зафиксировать точные HEAD обоих стеков и общий ancestor; сохранить их
   тестовые результаты. Создать третью рабочую ветку, не dev/main.
2. Разрешить console-config.sh вручную на уровне функций. В P-7 сохранить
   подтверждённый механизм DNS/AGH rollback и его маркировку incomplete;
   из B перенести private ownership, полный набор route tuples, pending
   journal, повторную проверку перед удалением и транзакции первого on/off.
   Ни один вариант файла целиком не выбирать через ours/theirs.
3. Отдельно проверить cleanup/EXIT/TERM и tunnel_undo: порядок компенсаций,
   сохранение evidence при недоступном AGH, отсутствие второй записи поверх
   чужого изменения, существующие admission/update barrier и CHANGE/EDIT locks.
   Проверить вложенный domain-list: service ID и transaction ID, обновление
   ownership только после проверенного применения, сохранность DNS state.
4. AGENT: сохранить оба журнала без переписывания, добавить новую запись
   интеграции. ROADMAP: свести статусы, сохранить открытые аппаратные ворота.
   SHA256SUMS сгенерировать из окончательных файлов, не выбирать сторону
   конфликта. VERSION/feed/release в этом пакете не меняются.
5. Запустить совместные функциональные регрессии: console-domain-lists,
   ads-dns-guard, smartdns-purge, service-ownership, service-transactions,
   service-faults и routing-state-errors; проверить доступные актуальные
   имена тестов в ветке P-7, а не создавать подменяющие проверки.
   Добавить сочетания AGH unavailable + retarget/off/refresh/TERM, rc=0 error,
   ошибку локального commit после DNS-мутации, ручной edit между снимками,
   reboot с pending и повторную попытку. Нельзя удалять failed assertions.
6. Один полный repository consistency и штатный CI на совмещённом HEAD,
   включая эмулятор. Прежние успешные длительные runs не перезапускать;
   новый run обоснован изменением совместного исполняемого кода.
7. Только после этого назвать программный кандидат совместимым. Приёмка
   реальных DNS, FQDN, VPN/ISP и клиентского пути на Viva остаётся отдельной.
   Установка, публикация и merge требуют команды владельца «Выпускаем».

## Ворота приёмки

- Пользовательские/unknown группы и маршруты не меняются ни при обычном
  применении, ни при компенсации; совпадения имени/состава недостаточно.
- При полном rollback состав, route tuples, DNS state и локальный pin
  соответствуют исходному снимку. При неполном — видимая ошибка и private
  recovery остаются, следующая сервисная операция запрещена.
- Выключение источника в будущем RS-6 освобождает только доказуемое владение
  этого источника; ручной список сохраняется. Нормализованный RS-5 audit
  не является адаптером реальной конфигурации и ничего не применяет.
- Нет нового демона, авто-replay по одному имени группы, увеличения
  ресурсных пределов, фиктивного CI PASS или заявления о проверке устройства.
