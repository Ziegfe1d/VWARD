## Движок

Подтверждённый источник второго корня: две ветки `handle_host` (ручной домен,
AdaptiveAuto) запускали `( { agh_bind; nslookup; } & )`. Внутренняя оболочка
становится сиротой с PPID=1 и argv движка. `adaptive_live_pids` выбирает точное
поле скрипта, поэтому awk list-watch не считается; `adaptive_core_count` исключает
только потомков найденных оболочек. Счётчик правильно отличает второй корень,
но старый движок сам создавал его. `by=` — вызывающий S91, не личность второго ядра.

Регрессия на настоящих процессах: работа 0,5 с даёт `2 -> 1` после перепроверки,
3,5 с — `2 -> 2`, с оставленным после выхода родителя процессом. Именно временем
жизни/моментом проверки объясняется разная реакция в предоставленных событиях;
личность конкретных PID 10:19/10:26/10:28 задним числом не восстановлена.
Теперь задачи остаются детьми Live, их PID учитываются и ожидаются при выходе.
Вложенная command substitution проверена отдельно: убийство только рабочего
родителя также создавало сироту; штатное завершение ждёт работу, S91 сохраняет
свой ограниченный stop всего дерева. Подсчёт, повторная проверка и защита от
независимого второго движка не изменены.

Источники запуска: cron-watchdog раз в минуту; supervisor recover_critical и
start_of по запросам realtime/network; boot, Панель/смена туннеля, vward-off,
возобновление updater. S91 start/stop/restart сериализуются CONTROL_LOCK;
service_healthy требует PIDFILE=LIVE_LOCK/pid, живой PID и ровно один корень.
clean_service останавливает все найденные оболочки/захват и снимает runtime-файлы.
Второй вызов S91 сам по себе новый Live при здоровом первом не запускает.

Воспроизведена задержка общей копии конфигурации: убитый читатель оставлял
pid-less lock; следующий ждал до 35 с, затем читал конфигурацию. Новые leases
содержат реальный PID оболочки (builtin `/proc/self`, не наследуемый `$$`),
точечное удаление только мёртвого владельца, отдельный временный файл читателя.
Живой читатель не лишается lease по возрасту. Конкурирующие читатели сохраняют
одно чтение. Старый pid-less lock обслуживается прежним правилом возраста.
Связь именно этого механизма с каждым стартом 34–39 с на Viva — гипотеза:
в исходном журнале нет снимков cache lock и этапов. Добавлены START_PHASE
restore/agh-prune/refresh с реальными elapsed/total/rc. Таймауты не увеличены.
Read-only вывод владельца в 10:50: один корень; running-config обычно 4,2–5,2 с,
отдельные 6,75/7,8/9,32 с. Нагрузка ndm этими строками не измерена.

## WAIT_DEGRADED

Health: исправный локальный интерфейс + хотя бы одна из двух HTTP-проб
через туннель (`1.1.1.1`, `1.0.0.1`); явный config/link down отменяет UP.
Первая плохая проверка — DEGRADED, вторая подряд — DOWN. Guard на DEGRADED
обнуляет down_streak и ждёт, не выключает туннель. `active=0` означает, что
fail-open guard сейчас не активен; это не число подключений и не отсутствие VPN.
Handshake не определяет GOOD; у Xray возраста WireGuard handshake может не быть.
Read-only в 10:50: UP, FAIL_COUNT=0, OK_COUNT=32, config/link up, обе пробы=1.
Состояние туннеля сейчас исправно. Причина единичной проверки 10:18 не доказана:
возможны реальный краткий отказ/задержка пробы, но ежедневная строка сама по себе
не доказывает длительный разрыв. Две пробы используют Cloudflare, поэтому не
покрывают независимые сети. Логику health в этом пакете не меняли.

## Режимы агентов (без изменения настроек)

| Агент | Наблюдение | Действие |
|---|---|---|
| Сеть | Проверки интернета/VPN/DNS, состояние и предполагаемые действия | Разрешает уже настроенные восстановление WAN/DHCP, перенос списков на резерв/возврат и fail-open туннеля; отдельные выключатели и MODE по-прежнему действуют |
| Компоненты | Контроль процессов/памяти/заданий, предложения | Разрешает перезапуск по памяти/запросу, остановку зависшего задания, официальную сборку AGH при его сбоях |
| Обновления | Проверка доступных обновлений и предложения | Разрешает предусмотренные политикой обновления Entware и официального AGH; отдельные auto-разрешения сохраняются |
| Обслуживание | Проверка сбоев/целостности и предложения | Разрешает предусмотренный ремонт падающих пакетов, curl/HTTPS, DoH и файлов Entware |

В наблюдении предложение ограничено одним одинаковым действием в час,
хранятся последние 200. При обоих режимах сохраняются обязательные действия:
запуск остановленных программ VWARD (включая S91), Панель/SSH, исключение
молчащего AGH из DNS-цепочки, механизм обновления VWARD, ротация журналов.
Режимы владельца не менялись. Перенос списков потерянного туннеля дополнительно
требует VWARD_LOST_MOVE=auto; выбор «Действие» сам его не разрешает.
