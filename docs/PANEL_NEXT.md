# Панель VWARD: план следующего выпуска (решения владельца 2026-10-17/18)

## Скорость

- Снимок данных всех экранов в оперативной памяти роутера; Панель только читает его (~10 мс).
- Обновление снимка по частям: конфигурация Keenetic перечитывается только после изменения
  (`show last-change`), туннели - по событиям vward-sentinel, остальное - по своим файлам.
- Копия снимка на флешку - только при изменении и не чаще раза в 10 минут (для показа после
  перезагрузки).
- Браузер: последнее известное показывается сразу; «что новее версии N?» долгим опросом
  (до 25 с); приходят только изменившиеся части.
- Нажатия срабатывают на экране сразу, роутер подтверждает в фоне, при отказе - возврат и
  сообщение.
- Файлы Панели сжаты при сборке и кешируются до следующего обновления VWARD.
- Тест скорости в обязательных проверках: эмулятор с «медленным Keenetic» (5 с на чтение
  конфигурации); любой запрос Панели < 300 мс, изменение видно < 2 с, полная конфигурация -
  только после изменения.

## Не больше 4 нажатий до действия

- Счёт: тап по кнопке, строке, вкладке, переключателю; ввод текста не считается, кнопка после
  него считается; подтверждение опасного действия считается; старт - любой экран.
- Исправить: «Установить»/«Обновить» прямо в строках «Обновлений» (VWARD, AdGuard Home,
  Entware); клиенты Wi-Fi прямо в «Сети»; «Источники» рекламы строкой на главной странице
  Рекламы, поле добавления сверху; строка «Сервер» VLESS открывает список с поиском, кнопка
  «Лучший сервер».
- Общие правила: поиск в шапке открывает пункт подсвеченным; главное действие - в строке;
  уведомление всегда с кнопкой действия; своё нижнее меню; подтверждение только для опасного.
- Тест: обход всех страниц считает кратчайший путь от Обзора до каждой кнопки и переключателя;
  глубже 4 - проверка не проходит (исключения названы явно: просмотр файлов, там поиск).

## Маршруты - одна страница

- Сверху поле «Домен, IP или подсеть»: проверка и сразу «В VPN» / «Напрямую» / «Smart DNS»;
  оно же ищет по всем спискам и доменам внутри них.
- Списки тремя сворачиваемыми группами, строка одного вида (название · домены/подсети · туннель,
  переключатель «VPN/напрямую» и выбор туннеля прямо в строке):
  - Ваши: «Основной» (бывшие «Мои домены»: домены, IP, подсети, булавка «всегда через VPN»)
    и списки, созданные в Keenetic;
  - Сервисы: включённые сервисы каталога с их подсетями, «Добавить сервис»;
  - Автоподбор: найденное VWARD, переключатель внутри.
- Фильтры: все / через VPN / напрямую / с ошибками / по туннелю; сверху - требующие внимания.
- Smart DNS - отдельный блок: честный статус (клиент DoH слушает или нет), домены и откуда
  они, сервер, «Не пускать домены Smart DNS в VPN» (бывший «Агент Smart DNS»). «ИИ-сервисы» -
  быстрый экран со ссылкой туда же.
- «Как VWARD ищет домены» (свёрнуто): источники, расписание, история автоподбора и сверки.
- Уходят: «Мои домены», «Доменные списки», «IP-категории», блок Smart DNS на странице списков,
  отдельный блок «Автоподбор». Старые адреса ведут в новые места.
- Страница любого списка одинаковая; у «Основного» и «Автоподбора» нет удаления; список,
  совпадающий с сервисом каталога, - предложение заменить сервисом (по нажатию).
- Пустой список - серым «пустой» с «Удалить список». Smart DNS у списка - коротко
  («в обход VPN · Smart DNS: 6 доменов»).
- На странице туннеля - только «Списков через этот туннель: N» с переходом в Маршруты по фильтру.

## IP-категории -> Сервисы

- Подсети сервиса включаются вместе с сервисом (Telegram, Discord, Meta, Google Meet, X, Netflix).
- Сети доставки контента (CloudFront, Fastly ...) не включаются по умолчанию; группа в конце
  «Сервисов» с предупреждением.
- При обновлении: включённые по умолчанию и не тронутые владельцем CloudFront/Fastly выключаются,
  уведомление.
- meta и facebook - один сервис «Meta (Facebook, Instagram, WhatsApp)».
- Понятные названия вместо технических (google_meet -> Google Meet).
- Свои IP и подсети - в «Основном» списке; защита от домашних адресов и слишком широких подсетей
  (/8, 0.0.0.0/0) с подтверждением; подсказка «уже покрыт подсетью».
- ИИ-сервисы в «Сервисах» показаны как «через Smart DNS - настраивается в ИИ-сервисах».

## Ошибки вида

- Плашка «Роутер отвечает медленно» наезжает на текст под заголовком.

## Система → Хранилище (скрин 2026-10-18)

- Строка «Флешка»: длинные пути в подписи сжали значение, и «ошибок: 7» встало столбиком по
  букве. Значение никогда не переносится по буквам; в строке - коротко «ошибок: 7 · в 2 местах»,
  пути - на отдельной странице «Флешка» (и под «?»).
- Страница «Флешка»: ошибки по времени, повреждённые места, что делать (проверка fsck на
  компьютере, замена). Повреждены старые копии VWARD (`/opt/var/backups/...`): кнопка
  «Убрать повреждённые копии» - только для папок копий VWARD, переименованием в `.damaged` и с
  исключением из сверок и копий, ничего чужого; удалить их можно позже, когда флешку проверят.
- «Целостность файлов» - на ту же страницу «Флешка»: последняя сверка, найденное, история.
- Значения-ссылки синим («каждый час») - по общему правилу: значения не синие, ссылка - стрелка.

## Система → Стабильность (скрин 2026-10-18)

- Отдельного блока с причинами нет: строки со сбоями стоят сверху, по убыванию вклада в индекс;
  под процентом - подпись из названий этих строк («починки · пропадания · Keenetic»).
- Строка «Keenetic отвечает вовремя»: название переносится в 3 строки, значение длинное.
  Значение коротко («112 отказов»), «за сутки · последний 18.10, 03:35» - в подписи; подробности
  - журнал «кто ждал» (keenetic-slow.log) с программой и запросом.
- «Починки 671 из 1248 помогли» - что чинилось чаще всего (например, перезапуски туннеля, что
  отвечал 2 минуты и падал) и ссылка на журнал; починки выключенного владельцем туннеля не
  считаются.
- Статусы строк - по общей схеме (Работает / Сбои: N / Не работает), значения не цветом текста.

Расчёт индекса (одобрено 2026-10-18; пункты 1-4 - в ближайший выпуск):
1. Пропадания программ: доля часов без пропаданий и утечек, а не минус 10% за каждое (сейчас
   10 пропаданий обнуляют часть и за сутки, и за неделю).
2. Починки: по случаям (проблема возникла - решилась или нет), а не по попыткам; 600 перезапусков
   одного туннеля - один случай. Починки выключенного владельцем туннеля не считаются.
3. «Keenetic отвечает вовремя»: доля отказов от всех запросов, а не «больше 10 - 0%».
4. Сутки и неделя - один расчёт: туннель, обновления, HTTPS и Keenetic хранятся по часам неделю
   и входят в недельный индекс.
5. Туннель: все включённые туннели (VLESS тоже), не только туннель маршрутов.
6. «Нагрузка» по заданиям - за сутки, а не с загрузки роутера.

Вид:
- Описание весов - под «?»; на экране одна строка «95% и выше - норма».
- Строка со сбоями открывает свой журнал: починки - что чинилось; пропадания - какая программа и
  когда; Keenetic - журнал «кто ждал».
- «Последние события»: повторы свёрнуты («AWG пропал, запущен снова ×600, 17.10 14:02-19:40»).
- График по часам за сутки (24 столбика, цвет по индексу часа); нажатие - события этого часа.
- На графике - отметки установки выпусков VWARD.

## Установка (первая установка на роутере владельца 2026-10-18)

- Установщик без вопросов: пакеты ставит сразу, туннель не выбирает. Выбор туннеля для
  сайтов, AdGuard Home, реклама, Smart DNS - мастер первого запуска в Панели VWARD.
- Установка без VPN: без туннеля ставится всё, кроме маршрута AdaptiveAuto; маршрут и
  туннель для сайтов - когда в Панели добавлен первый туннель.
- Проверка пакетов по `opkg list-installed`, а не по путям файлов: в Entware 2026-10
  tcpdump в /opt/bin, mod_setenv встроен в lighttpd 1.4.82 (установка падала).
- Инструкция: черновик в git stash основного репозитория; «missing initrc» перед
  установщиком Entware - норма, не ошибка; `no opkg disk` перед `opkg disk`.

## VPN → Туннели (скрин 2026-10-18, после переустановки на пустую флешку)

Техническое:
- Туннель движка VWARD без настроек (стёрлись с флешкой) показан как обычный «Выключен», а
  туннель по умолчанию - «выключен агентом: туннель не отвечал». Нужно: статус «Нет
  настроек», кнопки «Настроить заново» (подписка / .conf) и «Удалить»; агент такой туннель
  не проверяет и не «чинит».
- Туннель по умолчанию без настроек заменяется на месте (без «добавить новый, перенести,
  удалить старый»); удаление по умолчанию сейчас скрыто - для туннеля без настроек
  разрешить с выбором, куда передать списки.
- Ползунок не переключается и ничего не говорит: для туннеля без настроек - отказ с
  причиной рядом со строкой; любой отказ возвращает ползунок и пишет причину.
- У «de-vless» ползунок включён, а статус «Выключен агентом» - противоречие. Ползунок -
  желание владельца, статус - факт; при «выключен агентом» ползунок показывать как есть,
  но в строке ясно: «включён вами · агент отключил: …».
- «отказ, списки на резервном канале», хотя другого туннеля нет и списки идут напрямую;
  на странице туннеля - «напрямую». Один текст: «списки идут напрямую».
- Обзор: «VPN 0 из 1», а туннелей в списке 3 - один счёт везде.
- Копия настроек туннелей во внутренней памяти Keenetic и восстановление после
  переустановки (предложено владельцу, ждёт решения).

Оформление:
- Левая колонка узкая: «по умолчанию» переносится по буквам («умолчани/ю»), причина в 6
  строк. В строке - только название и «по умолчанию»; причина - на странице туннеля.
- Статус дважды (под названием и справа) - оставить один, справа, коротко
  («Отключён агентом»), без переноса.
- Строка «Нажмите на туннель, чтобы открыть его; переключатель…» - убрать.
