Команды исключительно диагностические, конфигурацию не меняют. Они создают только
свои временные скрипты, закрытые файлы вывода и указатели в `/tmp`, с ротацией.

1. [p7-router-acceptance.txt](../tools/termius/p7-router-acceptance.txt): шесть вставок,
   включая запуск. Выполнить один раз. Восемь правил сопоставляются по точному URL
   с текущим private config и максимум 20 локальными копиями `smartdns.conf.*`.
   Вывод содержит домен, номер сервера и имя файла-доказательства, без URL/токена.
   `owner=UNKNOWN` означает недостаток доказательств, а не разрешение удалить правило.
   Проверяются DNS-привязки, маршруты FQDN, ограниченные записи сохранённого состояния,
   API AGH только GET с приватным auth-файлом, порт DNS, нагрузка/память/процессы.
2. [p7-client-path.txt](../tools/termius/p7-client-path.txt): пять вставок, включая запуск.
   Ввести адрес ОДНОГО проблемного устройства и фактический домен приложения;
   пустой домен означает только `api.ozon.ru`. Запустить приложение в течение 15 секунд
   захвата. LAN ограничен MAC устройства, если он найден через neighbor/ARP: видны
   IPv4 и IPv6; иначе фильтр только по введённому адресу, и другая семья не доказана.
   WAN/туннель ограничены временем/числом заголовков TCP/UDP, содержимое не печатается.
   В конце можно проверить локальный маршрут одного реального назначения из захвата.
   Его вывод сам по себе не является доказательством клиентского пути.

Вставлять каждый блок от `clear` до `EOF` отдельно, последний блок запуска отдельно.
Все строки ASCII, до 60 символов; вставка до 1,4 КБ; синтаксис sh проверен.

## Не исправлено: нужны дополнительные данные

- Принадлежность восьми старых правил после стирания URL прежним clear. Если private
  config/копии не доказывают точный адрес, нужен локальный исходный URL/backup владельца;
  его не запрашивают для публикации и не угадывают по домену провайдера.
- Причина сбоя Ozon: нужен совпадающий с временем запуска трафик устройства и решение
  для `api.ozon.ru`, а не очередной DNS роутера. Настройки Private DNS/DoH нужны только
  если запросы устройства обходят роутер; их состояние пока неизвестно.
- Lampa: фактический домен установленного приложения/источника вместо предположения
  `lampa.mx`; результат запуска и совпавший трафик.
- Supercell: название конкретной игры, время запуска, реальные UDP/IPv6 назначения;
  отсутствие A у двух имён не доказывает причину сбоя игры.
- LOAD: после отдельно разрешённой установки нужны 24 часа существующих счётчиков
  деградаций/медленных RCI/STOP reason и фактическая нагрузка в покое. Разовый top и CI
  не подтверждают суточные критерии. Новый постоянный сборщик не добавлялся.

## Оставшиеся риски и критерии приёмки

- Пока API AGH недоступен, синхронный полный откат невозможен. Потеря его данных
  устранена, но требуется восстановление после возврата API по приватному файлу,
  с сопоставлением текущих upstream и отдельным разрешением владельца на изменения.
  Автоповтор, новый страж/очередь и запуск восстановления на роутере не добавлялись.
  Незавершённые копии намеренно не ротируются: владелец убирает их после проверки.
  При kill -9/потере питания нет обещания автоматического восстановления или fsync.
- Совпадение домена в FQDN со списком не доказывает наполнения группы и пути клиента.
  DNS роутера не равен DNS приложения. Аппаратное ускорение, NAT и шифрование туннеля
  ограничивают tcpdump: отсутствие совпавших пакетов означает недостаток данных.
- После разрешённой установки: подтвердить фактическую версию и флаги, успешные
  DNS-привязки/ограниченный повтор отказов, точечность clear/remove и отсутствие
  возвращения удалённых правил при штатном возврате группы, без ущерба соседним правилам.
- Для каждого проблемного приложения: сопоставить DNS устройства, LAN и реальный выход
  IPv4/IPv6 TCP/UDP; подтвердить работоспособность приложения, не только успешный DNS.
- Через 24 часа: ложных деградаций <=5/сутки; RCI >1 с <=1%; нет одновременно тяжёлых
  cron-задач; у каждой остановки route-engine есть причина; load 1 мин в покое <1,5.
- Полный P-7 принимается только после зелёного CI нового кода и реальной приёмки.
  VERSION/feed/подпись не менялись, PR не сливались, роутер не менялся.
