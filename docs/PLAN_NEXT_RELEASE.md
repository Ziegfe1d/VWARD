# План следующего выпуска (после `0.2.0-rc.2.fix.1`)

Улучшения и новые возможности, которые владелец 2026-10-03 перенёс из фикса
[`FIX_PLAN_RC2_FIX1.md`](FIX_PLAN_RC2_FIX1.md): в фикс входит только устранение ошибок,
стабильность и скорость.

## Панель VWARD

1. Плитки на «Обзоре» одного размера; в настройках плиток переключатель «Показывать дополнительные
   подписи», подписи занимают одно и то же число строк (1 или 2), чтобы плитки и строки списка совпадали.
2. Проверка обновлений: «Проверить сейчас» и автоматическая проверка по расписанию, как у установки
   (выбор времени, автоустановка отдельно).
3. Дизайн, четыре пункта: кнопки с длинным текстом во всю ширину; длинное значение под названием
   строки; серые заготовки вместо прочерков при загрузке; «обновлено N мин назад» у блока вместо
   жёлтой плашки.
4. В «Система → Стабильность» показать события `TCPDUMP_RESTART` (интерфейс и число быстрых падений).

## Туннели

1. Подписка VLESS как один туннель-группа (предложение владельца 2026-10-04). Сейчас из подписки
   создаётся туннель на один выбранный сервер. Нужно: добавить подписку целиком («Все серверы»), на
   странице туннеля - список серверов, сгруппированный по странам, у каждой страны и сервера свой
   переключатель «использовать»; режим «подбирать автоматически». Программа сама замеряет
   доступность и пинг серверов, отключает недоступный (ответа нет несколько проверок подряд) и
   включает обратно, когда он снова отвечает; данные подписки обновляются по расписанию (новые
   серверы появляются, пропавшие убираются, выбор владельца сохраняется). Основа: движок
   `vward-vless-engine.sh` (один Xray на туннель) и `vward-tunnel-quality.sh` (замеры); вопросы:
   один процесс Xray на группу с балансировщиком/`observatory` или переключение сервера в
   конфигурации, лимит памяти на MIPS (30-60 МБ на процесс), замер без трафика через сервер.

## Решения владельца

- Резервный DNS: если AdGuard Home не отвечает дольше 2 минут, временно добавлять в Keenetic
  name-server провайдера и убирать, когда AdGuard Home поднимется. Плюс: интернет есть всегда.
  Минус: пока резерв включён, реклама не фильтруется и Smart DNS (Aeternia) не работает.
  Включение по умолчанию - вопрос владельцу.
- Токен Aeternia: запускать `https-dns-proxy` так, чтобы токен читался из файла, а не из аргументов,
  если программа это позволяет.

## Замечания владельца 2026-10-04 (скриншоты: Диагностика, Компоненты, туннель, Стабильность)

Записано по просьбе владельца, делать после его команды.

**Технические**

1. Туннель контура AmneziaWG 2.0 не передаёт трафик (IP не определён, потери 100%): диагностика
   рукопожатия, трафика и ошибок движка; если сервер ни разу не ответил - так и писать.
2. Самопроверка «VPN-туннели» - «Норма», хотя один из двух не работает, и «код последней проверки: 0»:
   считать каждый туннель, «2 туннеля, 1 не отвечает: имя», статус «Внимание».
3. «Smart DNS мимо VPN - Сбой»: домены Smart DNS уходят в туннель (они же есть в VPN-списке): Smart DNS
   главнее, его домены исключаются из VPN-списков, у проверки кнопка «Исправить».
4. «Цепочка DNS - Внимание» без `ip name-server ...:65053`, хотя DNS отвечает: проверять, что DNS
   реально отвечает через AdGuard Home, а не одну строку настройки.
5. «Защита VPN» выключена: выяснить, кто выключил; если не владелец - вернуть; причина и «Включить»
   рядом со статусом.
6. Стабильность 65%: 983 падения программ, 124 из 537 починок помогли (почти всё - tcpdump до fix.7):
   разбивка по программам; повтор бесполезной починки откладывается.

**Оформление**

7. Страница туннеля контура: «Обфускация - Выключена», «Keepalive - выключен», «Сервер -» неверны
   (берутся из прошивки): брать из конфигурации VWARD.
8. «Чтобы сменить сервер, добавьте новый туннель и удалите этот»: «Заменить конфигурацию» и для
   туннелей контура.
9. Удаление туннеля: подпись «Куда передать списки и подсети» сжата в три строки рядом со списком -
   на телефоне подпись над списком.
10. Время в «Компонентах» как `2026-10-04T18:30:46Z`: местное время «04.10 21:30».
11. «Smart DNS мимо VPN»: длинная строка с IP и `opkgtun2` - коротко имена доменов и «Исправить».
12. У строки «Цепочка DNS» нет стрелки к подробностям, у соседних есть.
13. Статусы парами по смыслу, без смешения: у того, что включается и выключается, - «Включён /
    Выключен» (не «Норма» рядом с «Выключен»); у проверки - «Работает / Не работает» (или
    «Есть / Нет»). Слово «Норма» не использовать там, где противоположное состояние называется
    иначе. Пройти все списки статусов Панели VWARD (Компоненты, Диагностика, Стабильность, туннели).

## Страж цепочки DNS (владелец 2026-10-04, главное)

Было: после 00:00 AdGuard Home перезапускался по кругу (сторож VWARD перезапускал его, пока он
грузил списки), DNS всего дома не работал, а VWARD не умел убрать AdGuard Home из цепочки - его
убирали командами вручную (`ip name-server ...:65053` удалён, Aeternia отключена). С тех пор
AdGuard Home вне цепочки: реклама, скорее всего, не фильтруется. Перезапуск по кругу в fix.1
исправлен (один запускающий, 120 с на загрузку, растущие паузы) - проверить на роутере.

Нужно, чтобы VWARD сам:
1. Знал цепочку: устройства → Keenetic (53) → AdGuard Home (65053) → Aeternia / Smart DNS /
   провайдер; проверял каждое звено настоящим запросом каждую минуту (страж реального времени -
   сразу).
2. Звено не отвечает 2 проверки подряд или его программа перезапускается по кругу (3 раза за
   10 минут) - выводил его из цепочки: AdGuard Home - убрать `ip name-server ...:<порт>` и
   перенаправление порта 53 (последнее уже есть), Keenetic идёт к провайдеру; Aeternia / Smart
   DNS - их сервер заменяется провайдером. Перезапуски этого звена прекращаются, не по кругу.
3. Возвращал звено сам, когда оно 3 проверки подряд (5 минут) отвечает.
4. Писал об этом: уведомление «AdGuard Home выведен из цепочки в 00:14: не отвечал. Реклама не
   фильтруется. Вернётся сам, когда заработает», журнал.
5. В «Компонентах» и на страницах (AdGuard Home, Smart DNS, VPN) - переключатели «в цепочке»,
   с предупреждением, на что влияет выключение (как у VPN: «интернет пойдёт напрямую через
   провайдера»). Выключенное владельцем VWARD сам не возвращает.
6. Первым делом - вернуть AdGuard Home в цепочку самому VWARD (без команд), когда страж готов.

## Два стража вместо восьми (владелец 2026-10-04)

Сейчас: восстановление интернета, защита VPN (здоровье + страж), сторож маршрутизации (S91),
супервизор, страж реального времени (sentinel), DNS-страж рекламы, классификатор, обслуживание.
Каждый сам что-то запускает - отсюда гонки (перезапуски AdGuard Home по кругу).

Станет:
1. **Страж соединения** - всё, от чего зависит, идёт ли трафик: провайдер (переподключение по
   шагам), цепочка DNS (AdGuard Home, Aeternia / Smart DNS - вывод из цепочки и возврат, см.
   «Страж цепочки DNS»), туннели (перезапуск, смена сервера подписки, перенос списков на другой
   туннель или напрямую и возврат). Проверяет по порядку: провайдер → DNS → туннели; пока нет
   провайдера, не трогает DNS и туннели.
2. **Страж компонентов** - программы: VWARD (маршрутизация, Панель, программы туннелей, захват
   DNS), cron, AdGuard Home. Упала - запуск через одни «ворота» (пауза на загрузку, растущие
   паузы); падает по кругу - остановить, пометить «сломан», сообщить, звено вывести из цепочки
   через страж соединения; утечка памяти - перезапуск.
- Страж реального времени (sentinel) - не страж, а «глаза» обоих: мгновенно сообщает о событиях,
  сам ничего не запускает.
- Классификатор рекламы и обслуживание - обычные задания (раздел «Задания»), не стражи.
- Правило: запускать, останавливать и выводить из цепочки может только один из двух стражей;
  остальные просят его.
- В Панели VWARD - два стража, у каждого переключатель и список того, за чем он следит, с
  последним действием.
- Переход по шагам: сначала Панель и одно расписание на стража (старые скрипты внутри), затем
  слияние кода; каждый шаг - с тестами на эмуляторе роутера.
