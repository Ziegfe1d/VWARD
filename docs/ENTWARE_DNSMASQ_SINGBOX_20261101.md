# dnsmasq и sing-box в общем выпуске VWARD — аудит совместимости и состояние (01.11.2026)

**Решение владельца от 01.11.2026:** интеграция dnsmasq и sing-box входит в текущий общий
приёмочный выпуск (sing-box больше не отдельный fix.40). Оба компонента **по умолчанию выключены**:
«установлен, выключен» сохраняется после установки, обновления и перезагрузки. Xray остаётся основным
движком VLESS, AmneziaWG сохраняется, AdGuard Home — DNS по умолчанию. На действующем роутере ничего
не устанавливалось и не включалось.

## 1. Что проверено, а что — нет

| Вопрос | Источник | Результат |
|---|---|---|
| Модель/прошивка | self-test 31.10 | Keenetic Viva KN-1913, KeeneticOS 5.01.C.8.0-2, `arch: mips` |
| Архитектура Entware | self-test | **не доказано**: `mips` без порядка байтов. Для MT7621 ожидается `mipselsf-k3.4`; проверка на устройстве — `opkg print-architecture` (read-only) |
| Память | self-test | 254 MB, доступно 81 MB, load 5,79 в пике |
| Занятые DNS-порты | self-test | `:53` — `ndnproxy` (Keenetic); AGH — `:65053`; 8 процессов `https_dns_proxy` (Smart DNS DoH); `avahi-daemon` (mDNS) |
| Процессы VWARD-окружения | self-test | AdGuardHome, xray, lighttpd, vward-sentinel, crond; AmneziaWG-процесса нет (туннель в ядре/неактивен — не проверено) |
| Индекс Entware (`dnsmasq-full`, `sing-box-go`: версии, зависимости, размер, SHA256, postinst, сборочные теги) | `bin.entware.net` | **не проверено**: хост закрыт сетевой политикой среды разработки. Нельзя считать наличие `.ipk` доказательством работоспособности |

Поэтому код определяет возможности **на устройстве во время проверки** (вывод `dnsmasq --version` —
«Compile time options», `sing-box version` — «Tags»), а неизвестное считает неподдерживаемым.

## 2. Ожидаемые возможности (проверяются кодом, не принимаются на веру)

| Функция | Движок | Что требуется доказать | Если не доказано |
|---|---|---|---|
| `server=/домен/адрес`, `address=/домен/0.0.0.0` | dnsmasq | базовые функции dnsmasq | — |
| `ipset=` / `nftset=` | dnsmasq | опции `ipset`/`nftset` в compile options | не используются |
| DNSSEC, DoH | dnsmasq | `dnssec`; DoH в dnsmasq нет | DoH остаётся за https_dns_proxy/AGH |
| VLESS + REALITY | sing-box | `with_utls` в тегах (REALITY) | туннель остаётся на Xray |
| XHTTP | sing-box | в известных сборках sing-box транспорта XHTTP нет | **всегда Xray** |
| WireGuard | sing-box | встроенный endpoint/`with_wireguard` | остаётся на штатном WireGuard Keenetic |
| AmneziaWG | sing-box | не эквивалент WireGuard; поддержка не заявлена | **всегда AmneziaWG** |
| QUIC/Hysteria2/TUIC | sing-box | `with_quic` | недоступно |
| Cloudflare WARP | sing-box | WireGuard-профиль WARP + проверка | недоступно |
| Несколько URL подписок | VWARD | разбор подписки VWARD, не движка | — |

## 4. Аппаратные проверки (только по разрешению владельца)

1. `opkg print-architecture`, `opkg info dnsmasq-full sing-box-go` — read-only.
2. Загрузка пакетов в кэш без установки, сверка SHA256 с индексом, разбор `postinst`.
3. Установка «выключенным» на отдельном разрешении; замер памяти и CPU на Viva.
4. Переключения DNS и VPN-движка — только после адресного аудита и отдельного разрешения.

## 5. Пакет B — жизненный цикл внешних пакетов Entware (реализовано)

`components/runtime/lib/vward-entware-pkg.sh` — путь Update Engine 2.0 для **внешних** пакетов, отдельный от подписанных
файлов VWARD (их область владения не расширяется). Только `dnsmasq-full` и `sing-box-go`.

| Шаг | Как |
|---|---|
| Установленная версия | разбор `/opt/lib/opkg/status`; состояние службы: `off` / `enabled` (init `ENABLED=yes`) / `running` (`/proc/*/cmdline`, точный путь демона) |
| Кандидат | индекс Packages: версия, архитектура из `opkg.conf` устройства, SHA256, размер; **все зависимости уже установлены** — ничего не подтягивается неявно |
| Целостность и содержимое `.ipk` | размер и SHA256 по индексу; control (имя/версия); `preinst/postinst/prerm/postrm` не должны запускать/включать службу; данные только под `/opt`, никогда в пути VWARD, без `..` |
| Место | `2 × Installed-Size + размер пакета` на файловой системе `/opt` |
| Резерв | приватная копия conffiles (правки владельца); прежний проверенный `.ipk` в приватном кэше — иначе обновление отклоняется (нет пути назад) |
| Применение | `opkg install --nodeps <проверенный файл>` — один пакет, без ленты и `opkg upgrade`; затем все init-скрипты пакета `ENABLED=no` и остановка, если демон всё же запустился |
| Проверка | новая версия установлена, служба `off`; правки владельца в conffiles восстановлены, если пакет их перезаписал |
| Ошибка | откат на прежний проверенный `.ipk` (или удаление при первой установке) и проверка; не доказано — `unknown`, шлюз закрыт, повторы запрещены |
| TERM/SIGKILL/питание | `pending` до установки; `vward_entware_recover` только классифицирует по установленной версии и состоянию службы, ничего не повторяет |
| Разрешения | `VWARD_ENTWARE_APPLY=1` (выключено по умолчанию) и отдельно `auto_check/auto_download/auto_apply` в `/opt/etc/vward/entware.conf` (по умолчанию нет) |

Тест `tests/entware/check-entware-lifecycle.py` (sh и BusyBox, эмулированный корень с эмулятором opkg и настоящими
`.ipk`): отказ не из списка, архитектура, зависимость, SHA256/размер/повреждение/control, postinst со стартом службы,
путь VWARD и вне `/opt`; установка выключенной, «перезагрузка» (все init `start`) — служба не стартует; обновление
сохраняет правку conffile; postinst, запустивший демон в обход проверки, — демон остановлен и выключен; неудачное
обновление → прежняя версия; частичная установка + неудачный откат → unknown и закрытый шлюз; нет образа отката и нет
места → отказ до изменений; SIGKILL до/после установки → классификация без повтора; `sing-box-go` тем же путём;
Xray/AGH не затронуты, `opkg upgrade` не вызывается. Мутации 7 защит роняют тест.

Найдено и исправлено при разработке: разбор полей с цифрами (`SHA256sum`), обнаружение запущенного демона через
`ps w` обрезало длинные строки — заменено на `/proc/*/cmdline`.

## 6. Пакет C — dnsmasq (реализовано: чтение, генерация, проверка, план; DNS-writer не подключён)

`components/runtime/lib/vward-dns-mode.sh`:
- `vward_dns_mode_get` — `agh` по умолчанию (нет файла), `dnsmasq`/`native` по `/opt/etc/vward/dns-mode.conf`; повтор, мусор,
  symlink — `unknown`.
- `vward_dns_dnsmasq_render` — конфигурация 0600, детерминированно: `port=` (не 53 и не 65053), `listen-address=127.0.0.1`,
  `bind-interfaces`, `no-resolv`, `no-hosts`, `cache-size=1000`; upstream только `IP[#port]` (DoH dnsmasq не умеет); Smart DNS —
  `server=/домен/IP#port` **локального DoH-клиента**, URL отклоняется; Ads & Privacy Guard — `address=/домен/0.0.0.0`.
  Нет `dhcp-*`. Любая неверная строка — отказ без изменения прежнего файла.
- `vward_dns_dnsmasq_validate` — для ручных правок: `dhcp-*`, `interface=`, `enable-tftp`, не-loopback, внешние include,
  петли (`127.x#53`, собственный порт, `192.168.1.1`), занятые порты; если программа установлена — `dnsmasq --test` (только разбор).
- `vward_dns_mode_plan` — план переключения по фактам из read-only проб: оба обработчика работают / состояние неизвестно /
  режим не совпадает с запущенным → отказ; для dnsmasq — установлен, конфигурация валидна, порт свободен и не системный,
  **каждый домен Smart DNS сопоставлен**. Порядок: журнал → новый обработчик стартует вне цепочки и проверяется → цепочка
  заменяется одним шагом (старый вышел, затем новый вошёл — короткий разрыв, но никогда не два) → проверка через Keenetic :53
  (FQDN-маршруты и Smart DNS) → остановка старого → фиксация; откат — обратный порядок. Writer выключен: только текст плана.

Keenetic dns-proxy остаётся фронтом :53 во всех режимах — ipset FQDN-маршрутизации продолжает видеть ответы.
Тест `tests/dns/check-dns-mode.py` (sh и BusyBox); мутации 4 инвариантов (оба обработчика, DHCP, петля, системный порт) роняют тест.
