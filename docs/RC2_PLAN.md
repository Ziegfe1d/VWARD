## 3. Оформление и стабильность страниц

- [x] Один компонент «строка ввода с кнопкой внутри» для всех форм: поиск, проверка сайта,
      проверка рекламы, добавление доменов, подсетей, фильтров. На телефоне кнопка - значок,
      на компьютере - значок и слово. Enter = кнопка. Во время проверки - значок загрузки,
      размер поля не меняется.
- [x] Страницы не прыгают: место под данные зарезервировано, при обновлении меняется только
      текст значений.
- [x] Страница открывается сразу с последними известными данными, свежие подгружаются в фоне
      (кэш в браузере - теперь и для туннелей контура, обновлений, диагностики, сервисов).
- [x] Медленные запросы к роутеру и AdGuard Home: найти, ускорить или увести в фон; убрать
      «роутер не отвечал 10 секунд» при обычной работе. Страница AdGuard Home: семь запросов к
      нему - параллельно, каталог сервисов (сотни значков) хранится сутки. Фоновые задания
      после изменения сбрасывают кэш ответов роутера. На роутере не замерено.
- [x] Язык: без жаргона и расплывчатых слов. Время - точное («обновлено 28.09 14:32»),
      интервалы - точные («раз в час, последняя проверка 5 мин назад»), числа - с подписью.
      Технические имена (Wireguard0, OpkgTun1, коды ошибок) - только на страницах деталей.
      Проверено обходом всех 80 страниц в Chromium на эмуляторе роутера: нет битых ссылок,
      ошибок скрипта, «undefined/null», кодов ошибок; английские слова - только служебные
      имена в скобках, версии, домены и названия источников.

      туннель, открывается ли напрямую и через каждый туннель; не добавлен - «Добавить».
- [x] Кнопка «Сайт не открывается»: проверка интернета и туннеля (перезапуск при
      необходимости), обновление адресов сайта и маршрутов, перевод на другой рабочий
      туннель. Итог - что сделано, одной строкой. Сделано: перезапуск туннеля, через который
      идёт сайт, добавление в «Мои домены», если сайт открывается только через туннель VWARD;
      если открывается через другой туннель - кнопка перевести список. Обновление адресов
      сайта в Keenetic по кнопке - нет (Keenetic узнаёт их сам из DNS).

## 6. Реклама: проверить или заблокировать адрес

- [x] Первым блоком в «Рекламе»: вставить адрес (можно ссылкой целиком) → «Уже блокируется»
      (каким списком или правилом) или «Не блокируется» → «Заблокировать» (поддомен или весь
      домен) в пользовательские правила AdGuard Home, с проверкой; «Разблокировать» -
      исключение. Правила владельца пишутся в пользовательские правила AdGuard Home вне блока
      VWARD (его публикатор сохраняет всё вне блока), с проверкой, что AdGuard Home их принял.
      Раздел «Реклама» стал коротким: проверка адреса, «Блокировка рекламы» (выключатель и
      счётчики), «Списки и правила»; последние решения, публикация, разбор домена и настройки
      проверки - на своих страницах.

## 7. Несколько туннелей: автовыбор

План - в `ROADMAP.md`, «Автовыбор туннеля» и «Автоподбор доменов при нескольких туннелях».
- [x] Замеры туннелей (жив ли, пинг, потери), таблица и уведомления: `vward-tunnel-quality.sh`
      раз в минуту из проверки туннеля пингует через каждый туннель сразу, час замеров в RAM;
      «VPN → Несколько туннелей» (при двух и больше) - пинг, потери, разброс за 30 минут;
      строка качества на странице туннеля; уведомление о переключении.
- [x] Переключение при падении туннеля: «Защита VPN» переводит маршруты VWARD на лучший
      отвечающий туннель (меньше потерь, потом быстрее), напрямую - только если не отвечает
      никто; основной отвечает 3 минуты - маршруты возвращаются. Выключатели «Запасной туннель»
      и «Возвращать на основной». Ручной выбор туннеля отменяет возврат. Порядок запасных
      вручную - ещё нет (выбирается по качеству). Списки Keenetic со своим туннелем и сервисы:
      туннель списка не ответил 2 замера подряд - список переходит на лучший отвечающий
      (через тот же helper, что и в Панели, с проверкой), его туннель отвечает 3 минуты -
      возвращается; список, переведённый вручную, остаётся где есть. Видно в «Несколько
      туннелей» и в уведомлениях.
- [x] Выбор по качеству, критерий «Выбирать туннель по», ночной замер скорости. Выключатель
      «Выбирать лучший туннель» (по умолчанию выключен: переключение рвёт открытые
      соединения): туннель лучше текущего на 30% 15 минут подряд забирает маршруты VWARD, не
      чаще раза в 30 минут. Критерий: сбалансированно (потери и пинг, скорость - добавкой),
      скорости, отклику. Замер скорости - 10 МБ через каждый туннель по очереди: ночью
      03:00-05:00 (по умолчанию), раз в 6 часов или выключен; кнопка «Проверить скорость
      сейчас». Только при двух туннелях и больше. На роутере не проверено.
- [x] Проверка сервисов через каждый туннель и закрепление категории. Сервис на
      «Автоматически» раз в 30 минут (при двух отвечающих туннелях и больше) открывается
      через каждый туннель, как «Проверить сайт»; не открылся через свой - переходит на самый
      быстрый, через который открылся; открылся - остаётся (без дёрганья). Категория
      (например, «Игры») закрепляется за туннелем на странице «Сервисы»: её сервисы на
      «Автоматически» идут через него; сервис, закреплённый сам, остаётся на своём. На
      странице сервиса - «Проверка через туннели». На роутере не проверено.
- [x] Домен вне сервисов, который не открывается ни напрямую, ни через туннель VWARD,
      движок автоподбора проверяет через другие отвечающие туннели; открылся дважды - событие
      «открывается через «Финляндия» - добавьте его в список этого туннеля». Сам движок в
      другой туннель его не переносит.
- [ ] После rc.2: свой автосписок на каждый туннель (AdaptiveAuto по туннелям, домен переходит между
      ними): новые группы Keenetic, их сохранение, сверка и удаление при деинсталляции -
      большая переделка движка маршрутов; только с проверкой на роутере. После rc.2.

## 8. VLESS через Xray

- [x] Туннель VLESS из ссылок `vless://` или адреса подписки (обычной или base64), выбор
      сервера из списка; подключение OpkgTun, как у контура AmneziaWG. Xray - официальная
      сборка XTLS/Xray-core 26.9.9 (TUN-вход появился в 26.1.23), скачивается с GitHub только
      при первом VLESS-туннеле и сверяется с закреплённой SHA-256 архива. Поддержано: REALITY и
      TLS; tcp, ws, grpc, xhttp, httpupgrade. Адрес туннеля - 198.18.N.1/30 (диапазон для
      тестов, в домашних сетях не встречается). Туннель остаётся, только если через него
      открылась страница; иначе всё убирается. Проверено здесь: Xray подключается к уже
      созданному TUN-адаптеру (как делает Keenetic для OpkgTun) и не трогает его адреса;
      запрос прошёл TUN → Xray → VLESS-сервер и вернул HTTP 200. На роутере не проверено
      (память: около 30-60 МБ на Xray).
