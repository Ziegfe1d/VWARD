# Аудит дублей доменных групп Keenetic (2026-10-25)

Только отчёт (WP-F, режим `audit`). В Keenetic ничего не записывалось, группы не менялись;
правки - только после решения владельца.

## Данные

Источник: диагностики владельца 25.10 (self-test и vward-all), конфигурация Keenetic Viva.

| Что | Значение |
|---|---|
| Имён во всех FQDN-группах | 1265 |
| Из них YouTube в трёх группах сразу | 751 (59 %) |
| Группы с YouTube | `domain-list1`, `domain-list24`, `domain-list25` (все через `OpkgTun4`) |
| Доля адресов этих групп среди всех адресов FQDN-групп | IPv4 - 43 %, IPv6 - 73 % |

Ранее (журнал AGENT.md, конфиг 24.10): YouTube = list1 (172) + list24 (175) + list25 (175), Telegram =
list0 + list27, 192 домена сразу в нескольких группах, `domain-list26` нет.

## Что это значит

- Один и тот же домен в трёх группах: Keenetic хранит и обновляет его адреса трижды. Это лишняя
  нагрузка на ndm, особенно при зеркалировании FQDN (25.10 09:50:13 - 36 ошибок «FQDN mirroring
  failed, Resource temporarily unavailable» за 2 с, в ту же секунду RCI не ответил).
- Маршрут у всех трёх групп один (`OpkgTun4`), поэтому для трафика дубли ничего не дают.
- Связь с перебоями YouTube - гипотеза, не проверена.

## Предложение (не выполнено, ждёт решения)

1. Оставить YouTube в одной группе (например, `domain-list1`), из `domain-list24` и
   `domain-list25` убрать только имена, которые уже есть в `domain-list1`.
2. До правки - копия настроек и сравнение маршрутов по списку адресов YouTube до и после.
3. Счётчик ошибок «FQDN mirroring failed» до и после: ручная диагностика
   `tools/termius/diag-2-who-loads.txt`, раздел 7.

Ручные правила `ip name-server 8.8.8.8|1.1.1.1 ... on OpkgTun4` для доменов YouTube этим аудитом
не затрагиваются.
