# Единая Панель VWARD — рабочий прототип интерфейса

Изолированный прототип нового оформления **Панели VWARD**. Он не заменяет текущую Панель, не устанавливается через штатный установщик и не меняет настройки Keenetic.

## Что работает

- Единая страница: интернет, VPN, Smart DNS, доменные списки, карта назначенных маршрутов, распределение по выходам, сервисы, реклама, история уведомлений, версия и канал.
- **Реальные ответы** существующего CGI API: `status`, `lists-data`, `ai-data`, `ads-data`, `notes`. Реестр компонентов `status.parts.list`; скрытые в `status.parts.hidden` части не показываются.
- Значения и распределение списков строятся только из полученных API-ответов. История DNS и выдуманные графики не отображаются.
- Кнопка «Обновить» выполняет чтение (не более двух параллельных запросов, тайм-аут 12 секунд); автоматического опроса и дополнительного демона нет. Индикатор загрузки показывается без фиктивных чисел.
- Одна длинная страница с нижней панелью: **Обзор / Сеть / VPN / Маршруты / Ещё** на телефоне, все разделы на широком экране. Клик прокручивает страницу; ручная прокрутка обновляет активный пункт.
- Неактивные кнопки переключения режимов удалены: показаны только выбранный и фактический режимы из API. Запись и изменение маршрутов в прототипе отсутствуют.
- Ошибки, отсутствующие данные, 401/403, частичные ответы: **«—»**, без фальшивых зелёных статусов. Известный ноль разрешён только как явное значение API.
- Серверы, адреса, токены Smart DNS и другие секреты не выводятся. Внешних зависимостей и CDN нет. Карточки DNS и компонентов берут состояние из API; при отсутствии ответа ставят «—».

## Запуск

`index.html` и `VWARD_panel_live_prototype.html` содержат HTML/CSS/JS в одном файле. `app.js` сохранён как код более раннего прототипа и новым HTML не подключается. Для реальных показателей HTML должен раздаваться **с того же origin**, что и `/cgi-bin/api.cgi` штатной Панели VWARD. Открытие как `file://` показывает интерфейс и реальные состояния недоступности API, но не данные роутера.

Путь в репозитории: `prototypes/unified-panel/`. Для реального запуска на Keenetic требуется **отдельное разрешение владельца** на размещение HTML в веб-корне, с резервной копией и откатом. Установка/публикация в этой ветке не выполнялись. Не менять `main`, `dev`, маршруты, DNS и настройки VPN.

## Архитектурные ограничения

- API вызывается только через same-origin GET, запросы не меняют роутер.
- Панель не подменяет текущую транзакционную модель управления режимами. Выбор и фактически применённый путь показаны отдельно; указание маршрута из списка **не является измерением клиентского трафика**.
- Принято решение 13.11.2026 о замене AdGuard Home на `vward-dns`: в этом прототипе не зафиксированы настройки AdGuard Home, новая служба не объявляется установленной до реализации её API.
- Замороженные компоненты (в том числе контроль Wi-Fi-клиентов) не добавляются.
- Если API не сообщает время DNS, QPS, историю запросов или клиентские пути, соответствующие числа **не рисуются**. На схеме только действующие назначения маршрутов.
- Нет самодельного движка переключений, фонового сборщика, записи в DNS или второго watchdog.

## Проверки и приёмка

```sh
node --test prototypes/unified-panel/test.cjs prototypes/unified-panel/test-scroll.cjs
```

Приёмка на реальном Keenetic **не выполнялась**. Перед интеграцией в текущую Панель нужны проверки: подтверждение схем API на установленной версии; 320/390/768/1440 px; недоступность/истечение сессии; обрыв ответа; неполные данные, пустые списки; переключения в штатном интерфейсе и повторное чтение; отсутствие лишней нагрузки на ndm. Эта ветка не подлежит автослиянию или выпуску.

## Версия дизайна v5 (16.11.2026)

- В правой части шапки три реальные функции: **поиск** (разделы, названия списков, туннелей, компонентов и сервисов из API), **уведомления** (только полученные от API, счётчик лишь при наличии подтверждённого состояния прочтения) и **переключение темы** (системная / по времени / светлая / тёмная), как у действующей Панели VWARD.
- Интерфейс остаётся **одной прокручиваемой страницей**. Скролл синхронизирует нижнюю навигацию. Никаких имитаций переключения VPN/DNS.
- Эффекты: плавное открытие поиска и уведомлений, затемнение и размытие фона при наличии браузерной поддержки, однократное появление карточек, небольшая полоска загрузки. Уважает `prefers-reduced-motion`; на слабых браузерах эффекты отключаются. Новых библиотек и внешних CDN нет.
- **HTML5** (отдельного стандарта «HTML6» нет). JavaScript написан в стиле ES5 и использует `XMLHttpRequest` вместо `fetch`: это позволяет работать в более старых браузерах, включая IE11, без обязательных полифиллов. CSS содержит запасные значения для браузеров без CSS Variables/Blur/Grid. IE11 — режим упрощённой визуализации, **фактическое испытание в IE не проводилось**. Основные современные цели: Chrome, Edge, Firefox, Safari, Яндекс Браузер; доступен тест Chromium, но не всех движков.
- При отсутствии ответов API, неполных данных и ошибке авторизации вместо выдуманных показателей ставится **«—»**. Секреты не выводятся; непроверенный результат не окрашивается в успех. В пользовательском вводе и API нет вставки непроверенного HTML.
- `index.html` и `VWARD_panel_live_prototype.html` — автономные HTML со встроенным JS/CSS, `app.js` оставлен как исторический файл прежнего прототипа, **новой версией не используется**.

**Проверено локально:** 320, 390, 768, 1024 и 1440 px в Chromium; поиск, уведомления, темы, навигация, API-загрузка, отсутствие данных, 401, повреждённые и частичные ответы, XSS-безопасность текстовых полей. Node-контрактные тесты также проверяют отсутствие POST, постоянного опроса и современного JS-синтаксиса. Прогон на реальном Keenetic и независимая проверка в Safari, Firefox и IE11 ещё не выполнены.

**Статус:** предварительный концепт для обсуждения и возможной интеграции в `fix.43` (RC2). `dev`, `main`, установленная Панель и роутер не затронуты.
