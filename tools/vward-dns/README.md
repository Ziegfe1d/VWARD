# vward-dns для YouTube и Instagram

Пилот использует Go-библиотеку AdGuard dnsproxy и слушает UDP и TCP на `127.0.0.1:65153`. Принимает восемь доменов YouTube и Instagram и их поддомены. DNS к `8.8.8.8` и `1.1.1.1` уходит через сокеты, привязанные к Linux-интерфейсу VPN. При отказе обоих серверов модуль возвращает ошибку DNS. Keenetic остаётся перед ним на порту 53, чтобы видеть ответы для доменных маршрутов.

Ветка DNS по умолчанию, Smart DNS и фильтры Keenetic в пилоте остаются под текущим управлением. Для постоянного режима нужны проверка на Keenetic, восстановление после сбоя и подключение к Панели VWARD. Реклама и перенос правил AdGuard Home идут следующим этапом.

## Пакет

CI собирает `vward-dns-pilot` для MIPS little-endian, MIPS big-endian, ARM64 и AMD64. Для Keenetic Viva KN-1913 предназначена папка `vward-dns-mipsle`. Сверь `SHA256SUMS` из сборки того же коммита и помести программу и `pilot.sh` рядом. Пилот запускается отдельно от установки VWARD.

## Проверка на Keenetic

| Действие пилота | Результат |
| --- | --- |
| `serve` | Берёт VPN из профиля VWARD и запускает слушатель на запасном порту. Работает на переднем плане. |
| `probe` | Проверяет ответы на запасном порту для YouTube и Instagram. |
| `plan` | Читает настройки и рабочий файл DNS. Готовность подтверждается при 16 из 16 прежних привязок в обоих местах. Чужая привязка для выбранных доменов блокирует операцию. |
| `trial` | Временно направляет 8 доменов с Keenetic на порт пилота только при полном исходном наборе. Проверяет привязки `ndnproxy` и получение запросов через Keenetic. При выходе сверяет возврат прежних 16 строк в настройках и в рабочем DNS. |
| `restore` | Повторяет восстановление из сохранённого состояния, если запуск прервали или рабочий DNS остался неподтверждённым. |

Действия передаются скрипту `pilot.sh`. Оставь `serve` запущенным в отдельной сессии на время пробы. До временного переключения выполни `plan` и `probe`. Успешный итог требует двух записей, `result=trial_verified` и `result=original_dns_configuration_restored`. Если второй записи нет, сохранённое состояние находится в `/opt/var/lib/vward/dns-pilot/pending`. Операция не вызывает сохранение конфигурации Keenetic.

Если после отката в рабочем файле есть лишь часть прежних правил, делается один повтор применения выпавших строк. Пустой, чужой или изменившийся во время сверки набор оставляет восстановление неподтверждённым. Журнал восстановления удаляется только после проверки всех 16 строк в рабочем DNS.

Приёмка постоянного подключения включает ответы для обоих сервисов и путь DNS через VPN до и после переподключения туннеля. При недоступности модуля нужно проверить восстановление DNS и доменных маршрутов, включая фактическое поведение Keenetic для выбранных доменов при недоступном VPN.
